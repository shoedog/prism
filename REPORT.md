Design points implemented (DESIGN §5.1, brief):
- **E2 scalar gate** (C++ and `.h`): `primitive_type`, `sized_type_specifier`, `enum_specifier`, any pointer declarator, `auto` with a literal initializer. References, `type_identifier` (typedefs), qualified/template types, `decltype`, class/struct types and `auto` from anything else fail it.
- **E3 C++ escapes**, owner-wide by name: bare or parenthesized name as an `argument_list` element (call, `new`, direct and field initializers), brace-initializer element, `>>` operand, anything inside a reference/structured-binding initializer, by-reference capture (`[&x]`, `[&r = x]`) and every name of a lambda with a `[&]` default capture, bare initializer of a declaration whose type fails the gate. `<<` is not an escape (X3).
- **F6**: a `template_declaration` owner's own inner `function_definition` is not a boundary (`lexical_prune.rs::collect`, `c_prune.rs::walk`). Row T08.
- **E1 in C++**: bindings from `catch` parameters, `if`/`while`/`switch` condition declarations, init-statement declarations, range-for variables (loop variable scoped to the body). A condition declaration is not a plain write and never a D candidate. Class members and `this->x` stay ineligible.
- **`.h`**: a C-grammar owner in a `.h`/`.H` file gets the C++ rules. `.c` owners are unchanged.

## Readings taken conservatively (nobody was available to ask)
1. Any `Language::Cpp` parse gets the C++ rules, whatever its file name; `.h` means a `.h`/`.H` extension on a C-grammar file; every other C-grammar name stays off (G1 file).
2. A `template_declaration` owner runs only when it holds a direct `function_definition`; a class template, a nested template or a variable template is off (G1 kind).
3. A nested `function_definition` (a local class method) still turns the enclosing owner off (G1 nested); the method is its own owner. Lambdas are boundaries, not owners.
4. A catch parameter and a range-for variable have no def of their own in the DFG, so they are never D candidates; resolving them only stops a shadowed name from binding an outer local (rows `cp`, `rk`, `sh`). A condition declaration (`if (int v = f())`) is neither a plain write nor a candidate (it is also the tested value). An init-statement declaration is a plain write like a `for` init. `optional_parameter_declaration` (default arguments) and structured bindings are never eligible.
5. The escape set is a superset of the brief's: arguments are peeled through parentheses, both `?:` branches, comma sequences, assignment targets, increments and casts to reference types; designated-initializer values count; a range-for over a reference declarator escapes its range; `Foo f(a);` (parsed as a function declarator whose parameter type is `a`) escapes `a`.
6. A `[&]` default capture escapes every name inside the lambda; a by-value capture escapes nothing.
7. `e2_storage` in the ledger also covers function declarators (a `std::string s(x);` parse) because the diagnostic runs the C-mode eligibility check first.
8. The one-line template row of the brief ("on one line and on two") is the header sharing the function's line (`template <typename T> int f(T t) {`), not the whole function on one line (a same-line def/use pair is always kept).
9. The new cap test is `#[ignore]` in the default run: it needs more than 2,048 definitions and is minutes-slow in a debug build here. I ran it in a release test build (see the note below); the 6b cap test has the same cost and was left alone.
10. `lexical_prune_tests::prune_subset_and_labels_across_fixture_tree` is a shared test; I changed only its `c_pruned` predicate (C++ and `.h` now join `.c`).
11. Drop rows use `x + 1`, never a bare `f(x)`, because the bare argument is an escape; this is a recall cost the design accepts (call_arg is the main refusal in the ledger).
12. Retained-opportunity definition above is mine (regex write-only or `killed` label); it is a yield proxy, not an oracle.
