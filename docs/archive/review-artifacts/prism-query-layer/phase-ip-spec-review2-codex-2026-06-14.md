**REFINED REVIEW**

Findings:

1. **BLOCKER - Receiver-kind RTA fallback contradicts §7’s safety rule.** §7 says `T` does not satisfy a pointer-method interface unless `*T` is live (`phase-ip spec:197-206`, `260-261`), but §3/§11 preserve the existing empty-intersection fallback (`spec:101`, `258`). Current code falls back to all satisfiers when `satisfying ∩ live_types` is empty (`go.rs:646-657`). With satisfiers `{*T}` and live `{T}`, this admits `*T` anyway. Fix by making fallback receiver-kind-aware, or allowing it only when Go liveness is unknown/empty, not when the opposite receiver kind is observed.

2. **BLOCKER - The spec does not define the `T`/`*T` admission key vs bare method-body key boundary.** §7 needs `T` and `*T` as distinct satisfier/live keys, while current method lookup is bare receiver-keyed (`go.rs:417-427`, `660-672`). If satisfaction stores `*T`, FunctionId lookup misses; if it normalizes early to `T`, pointer-kind precision is lost. Fix: specify separate keys: receiver-kind admission key (`T`/`*T`), bare method-body key (`T`), and interface key; strip `*` only after RTA admission.

3. **MAJOR - Anonymous interface dispatch is not covered by the named-interface map.** §5 precomputes `interface_impls[(iface, method)]` from declared interfaces (`spec:135-143`), but recovered receiver types can be raw anonymous interfaces (`src/ast.rs:351-359`). The advertised caddy review surface includes `anon-interface SetConfig` (`baseline.md:61-64`). Fix with synthetic canonical interface keys for anonymous method sets, or explicitly defer them and remove them from §13 acceptance.

4. **MAJOR - `canonical_sig` is feasible but underspecified recursively.** Tree-sitter supports the needed top-level fields (`method_elem` params/result, grouped params, variadic params: node-types `1634-1670`, `1704-1746`, `2568-2590`). The gap is nested type serialization: `func(...)`, `interface{...}`, `map`, `chan`, `generic_type`, `qualified_type`, and type-set `type_elem`/constraints (`node-types:1147-1207`, `1420-1435`, `2258-2277`). Fix: define `canon_type(node)` recursively and mark non-basic/type-set interfaces non-dispatchable.

5. **MAJOR - Promoted method sets need embedded pointer kind, not unconditional promotion.** Current struct extraction strips embedded `*T` to `T` (`go.rs:291-295`), and promotion inserts methods without receiver-kind filtering (`go.rs:539-547`). §4 says promotion is unconditional, while §7 says value/pointer method sets differ (`spec:108-127`, `197-199`). Fix: retain embedded field kind and define Go method-set rules separately for interface satisfaction and selector-call owner aliases.

6. **MAJOR - Key normalization must be pinned before every Go owner lookup.** §9 says bare-name normalization applies to both sides (`spec:103`, `235`), but §5 pseudocode only normalizes the interface lookup after `owner_lookup(recv_ty, name)` misses (`spec:145-153`). Current `owner_key` does not strip `pkg.` or Go `[...]` generics (`resolution.rs:75-83`). Fix: define one `normalize_go_key` and require it for method extraction, promoted keys, interface keys, embedded names, and recovered receiver types before direct/promoted/interface lookup.

7. **MAJOR - RTA coverage can still under-prune or over-prune depending on fallback path.** Spec adds `&T{}` and `new(T)` (`spec:200-203`), but current Go liveness only sees composite literals (`src/live_types.rs:153-170`), while receiver recovery already treats `NewT()` as constructor-like (`src/ast.rs:3899-3920`). If another satisfier is live, an unrecorded factory/zero-value satisfier is falsely pruned; if intersection is empty, fallback fans out to all satisfiers. Fix by expanding Go liveness or documenting the recall/precision cliff with tests.

8. **MAJOR - Exact fan-out acceptance is still policy-thin.** The code will traverse every `Call(Exact)`/`Return(Exact)` in ExactOnly (`cpg/query.rs:403-470`), so Phase-IP’s uncapped interface fan-out enters precision-biased slices. §8 acknowledges this and relies on a fixture plus caddy U-method precision >= 0.81 (`spec:210-224`, `286-288`, `305-307`; baseline `35`). Add fan-out telemetry and a wide-interface fixture or explicit max-regression gate.

9. **MINOR - §10 needs a concrete replace operation.** The spec correctly identifies full recompute after incremental merge (`spec:247-252`; `src/cpg/build.rs:166-191`), but should state: clear `interface_impls`, remove all old `promoted_method_keys` aliases from `methods`, then repopulate from all files. Otherwise stale promoted aliases can survive because `remove_files` removes method entries only by `fid.file` (`src/call_graph.rs:736-740`).

Verdict: needs changes.
