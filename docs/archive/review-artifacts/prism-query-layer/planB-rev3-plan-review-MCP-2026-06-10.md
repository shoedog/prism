# Merged Plan Review — Plan B `taint_reaches` rev 3 (foundation slices)

Both lenses independently converged on the same core verdict: the slice ordering and coverage are sound, but Slice 5b's ordering oracle is unimplementable as specified, and two compile-order gaps (Slice 1, Slice 3a) break green-per-task execution. One lens-disagreement is resolved below (3a trait ordering); one finding is downgraded on the stronger lens's evidence (Slice 2 error mapping).

## BLOCKERS

**B1 — Slice 5b: the occurrence-rank↔node-rank oracle is unimplementable in principle; respecify AST-based before execution.** Both lenses confirmed independently: `CpgNode::Variable` carries no byte/column/ordinal — only `(path, file, function, line, access)` (`src/cpg/types.rs:28-35`, `src/cpg/build.rs:231-237`) — and `assemble_graph` inserts all Defs (Step 2) before all Uses (Step 3), iterating `dfg.defs.values()` in BTreeMap variable-name order (`build.rs:220-271`). Node rank therefore reflects access-kind-major, name-sorted insertion, never byte position; there is no node-side datum from which byte order can be recovered. On the plan's own round-6 counterexample (`sink(y); var y = u;` — 1 Def + 1 Use node, so the count-mismatch guard never fires), rank-matching maps the first byte occurrence (the use) to the first node (the Def), `def_before_use` returns true, and the gate admits exactly the backward hop it exists to block. Calibration (Coverage lens): the slice's own trio test would fail under this oracle, so TDD surfaces it mid-implementation rather than shipping corruption — but it's an unfixable-by-tweaking design dead end, hence a plan blocker. **Fix:** classify each same-line occurrence syntactically from the AST (identifier in declarator/assignment-LHS = def-position; others = use-position); `def_before_use` = any use occurrence at-or-after any def occurrence, conservative over the deduped node granularity; field paths (`o.data`) must match the path's base+field text, not a bare identifier. Drop or repurpose the "registration-order pin" test — the invariant it pins is false, and it would pass on benign fixtures (`var y = u; sink(y)`) while certifying nothing.

**B2 — Slice 1a: the vocab relocation does not compile without editing `src/reasoning/mod.rs` in the same subtask.** Current `reasoning/mod.rs` exports only `seeds` and `shape` (`src/reasoning/mod.rs:4-5`), but Slice 1 has `navigation/types.rs` doing `pub use crate::reasoning::types::*`. **Fix:** Slice 1a must explicitly list `src/reasoning/mod.rs` and add `pub mod types;` before touching `navigation/types.rs`. (Note: the plan's File Structure section adds `pub mod {types, order, taint_reaches}` only in later slices' context — make 1a self-sufficient.)

**B3 — Slice 3a vs Slice 5: `taint_trace_nodes(&[NodeIndex], Option<&dyn SameLineOrderView>)` references a trait that doesn't exist until Slice 5.** Lens disagreement, resolved: the Coverage lens claimed the `Option` parameter "correctly decouples Slice 3 from Slice 5," but the Executability lens is right — a trait object type in a signature requires the trait definition to compile, regardless of passing `None`. **Fix:** define the (one-method) `SameLineOrderView` trait in Slice 3a — trivially cheap — and land the oracle implementation in Slice 5; or defer the parameter to Slice 5 and change 3a's signature.

## MAJOR

**M1 — Slice 3d: `containing_function_node` must be name+span over actual graph nodes, with a defined `None` fallback.** Both lenses agree it must not route through `func_index` — keyed `(file,name)`, last-writer-wins (`build.rs:211`), so the two same-named `impl A::f`/`impl B::f` functions the slice targets collide there, and `function_nodes()` reads from that collapsed index (`src/cpg/query.rs:73-76`). The Coverage lens adds two refinements both should adopt: (a) pure innermost-span containment discards the `function` string the Variable node already carries and can mis-assign on overlapping spans (nested named functions sharing lines — the substrate's own round-7 fixture shape), turning intra-function edges into false `CrossFunction` boundaries and risking A3 golden drift; filter candidates by `name == var.function` first, then innermost-span. (b) Define behavior when no containing Function node exists (module-level vars, call-graph misses): fall back to the current `(file,function)` string comparison.

**M2 — Slice 5b: the count-mismatch warning has no delivery channel.** The planned API is `def_before_use(def_node, use_node) -> bool`, but the conservative-keep warning must land on `Trace.warnings` (`src/cpg/trace.rs:35-47`). **Fix:** return a structured decision (`{admit, warning}`), pass a warning sink into the gate, or give the trait a warning-drain API. Specify this in the same respecification edit as B1.

**M3 — Slice 5b/6: a single-file `SameLineOrder` over one `ParsedFile` doesn't match the Slice 6 call shape.** Sources can span files, and a `ParsedFile` alone cannot interpret `NodeIndex`s — the oracle needs CPG node metadata to even find the line/path to rank. **Fix:** make the view repo-wide (files + CPG metadata), dispatching by the node's file.

**M4 — Slice 5c: the gate must cover BOTH `RecoveredDefUse` sub-arms, by relation + same-line condition, and preserve the field-path split.** The Executability lens rated this MAJOR, the Coverage lens MINOR; MAJOR is right because it's a correctness hole, not wording: `taint_neighbors` recovers same-line uses via the simple-path arm and via the same-line subset of the field-path "any line" arm (`trace.rs:249-272`, `:311-380`), and `cfg_valid` admits same-line targets unconditionally (`trace.rs:439`) — so `sink(o.x); o.x = u` is the round-6 backward hop in field-path clothing with nothing else blocking it. **Fix:** word the gate as "any `RecoveredDefUse` edge whose def and use share a line"; gate same-line simple hops by occurrence order, preserve loop-carried field paths only through the CFG-cycle carve-out, and add the field-path variant to the trio's counterexample test.

## MINOR

**m1 — Slice 2c: name the error variant for all-sources-unresolved.** Lens disagreement, resolved in Coverage's favor: the plan's "reuse existing variants" is satisfiable as written because `QueryError::SymbolNotFound{seed}` exists (`src/navigation/types.rs:181-188`) — but the plan's substrate table lists only three variants and omits it, an implementer trap given the "never add a variant" rule. One-sentence fix: name `SymbolNotFound` as the all-sources-fail mapping (including all-empty loc seeds) and correct the substrate table.

**m2 — Slice 1c/8: the clip-repair call site as written never reaches the wire.** The graph clip lives inside private `build_result` (`src/mcp/output.rs:166-174`), which `shape_result` calls repeatedly inside a binary search with each candidate rendered and serialized at construction (`:120-137`, `:192-193`). `repair_after_clip(kept)` must run inside `build_result`, on the shaped clone, between the graph clip and `render` — not after `shape_result` returns. One-sentence plan fix.

**m3 — Slice 5a: the one-lined-loop case rests entirely on an untested CFG self-loop.** For a fully one-lined `while`, the back-edge is `from_line == to_line` (`src/cfg.rs:269-285`) → a ControlFlow self-loop on the line's single Statement node (`build.rs:431-441`); nothing tests this anywhere, and after 5c the cycle carve-out becomes the only thing keeping round-9 semantics on one-liners (the use is byte-before the def). A `reachable_forward`-style "reachable back to itself" implementation returns false on a self-loop (`query.rs:96-106`) — the exact trap the plan warns about, one level down. **Fix:** add the one-lined `while` variant to 5a's tests and require that an edge `n→n` counts as a cycle.

**m4 — Slice 3d: the classifier asymmetry is undocumented and two comments go stale.** `forward_reachable_in_function` stays name-keyed (`trace.rs:290-309`) while the BFS boundary moves to node identity — safe direction (only over-fires `BoundaryExited`), but it contradicts `trace.rs:286-289` and `shape.rs:56-58`, both of which assert the BFS and classifier cannot diverge. Either lift the classifier to node identity in the same slice or update both comments to document the deliberate asymmetry.

## Verified-sound (do not re-litigate)

The `SinkResult` reshape is genuinely emission-safe (zero constructors repo-wide); the 1a relocation preserves `Evidence.reasoning` byte-compat (consumer imports via `crate::navigation::types`, serde untouched); the 5a `cfg_reachable_lines` self-membership claim is correct; the 3a degrade-guard recomputation invariant (ALL Variable nodes at each root's line) is right and the named regression pins it; Slice 2b's param-at-function-start-line convention matches the substrate deliberately; gating only the node-precise BFS is sound; sequencing (wire-cap → freeze → seeds → trace → accessors → oracle → frontier → witness → MCP) lands every emission-shaping decision before the first emitter; deferred items (memoization, `Evidence::new`) are safe to defer.
