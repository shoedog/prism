# Merged Spec Review — Tier-A Accuracy Harness + Dev-Loop Test-Time Reduction (rev 1)

Both lenses returned full reviews (no error markers). Verified shared baseline both relied on: 121 `[[test]]` targets and exactly 24 leaf test dirs are exact; `FunctionInfo` (`src/ast.rs:49`) is public and holds the §2.3 fields — the gap is wiring, not privacy; the adjudicated-not-auto-failed contract, PEP 544 seams, and the four-measurement hybrid are sound and verified against the repo.

## BLOCKER

1. **§2.5/§2.6 — `CallEdge` and the Prism JSON extraction rules are undefined.** Current `callers` puts the *caller function span* in `item.location` with the call-site line only in `why.CalledBy.call_site_line` (`src/navigation/queries.rs:175-196`, `src/navigation/types.rs:49-52`); `callees` puts resolved *callee definitions* in `item.location`. Without explicit field definitions (caller def, callee def, call-site file/line/col, direction) and per-query extraction rules, the comparison layer is unimplementable or silently wrong. **Resolution:** specify the `CallEdge` dataclass and the exact JSON paths per query direction in §2.5.

2. **§2.4/§2.9 — the source-file universe per corpus is undefined.** The `prism` corpus is "the repo itself," but repo loading indexes every supported extension (`src/repo_loader.rs:277-293`) including non-Rust fixtures, while the oracle sees only the corpus language. **Resolution:** define the exact file set per corpus (language filter, skip rules) and require both oracle and Prism inventories to be filtered to the same set.

3. **§2.5 — symbol+file seeding breaks on the stratum that matters most.** The resolver returns `AmbiguousSymbol` for multiple same-name definitions in one file (`src/navigation/seed.rs:57-78`) — common for class methods, i.e. exactly the `C-method` stratum. **Resolution:** seed sampled definitions by location/start-line, and define how SUT-side errors are counted.

4. **§4 — three of five WP1 gates can flip on events unrelated to what they certify.** (a) G1's `C-method` clause assumes the `target`-class failure is sampled, but sampling is seeded-random over the inventory — any added function reshuffles it. (b) G2 requires rediscovering the `module_deps`/`load_repo` diffs, same problem. (c) G1's U-stratum threshold doesn't say raw or corrected — and the seeded oracle-misses drag raw down (`module_deps` raw P = 5/6 ≈ 0.83 alone), making the gate a function of sample composition. **Resolution:** pin the G1 `target` probe (`src/algorithms/taint.rs:1276`) and both G2 symbols as dedicated probes outside the random sample (the spec already uses this mechanism for `AmbiguousSymbol`), and define G1 on adjudication-corrected metrics or exclude pinned probes from its denominators.

5. **§3.1 — WP2 needs an explicit migration table.** Both lenses confirmed the 24-dir count is mechanically derivable, but the spec never enumerates it, and "per existing tests/ subdirectory" is ambiguous against `tests/common` and `tests/fixtures`. The G6 sweep is also mis-aimed: the coverage test has *three* path lists (`all_test_files` at lines 106 and 325, `test_files` at line 472) plus a fourth matrix consumer at line 987; `scripts/extract_tests.py` is a dead script with zero `--test` references; and `CLAUDE.md` still says `cargo test --test integration_coverage`. **Resolution:** add the table (new target names ← absorbed old targets, module names, excluded dirs, preserved `required-features`), include all three path lists in the sweep, grep for *path-style* references (`tests/<dir>/<file>.rs`) in scripts/CI rather than only `--test <name>`, and list `CLAUDE.md`'s Build & Test rewrite as an explicit deliverable.

## MAJOR

6. **§2.3 — the `nav functions` implementation contract is incomplete, and its stated invariant is already false.** `NavQuery` has no `Functions` variant (`src/main.rs:230-301`), and nav indexes `CpgNode::Function`, which carries no `kind` (`src/cpg/types.rs:12-19`) — so "wire to FunctionTable" is a real seam, not a one-liner (corrected framing: both second passes converged that this is wiring, not privacy). Separately, decorated Python functions are double-captured — the query matches both `(function_definition)` and `(decorated_definition)` (`src/queries.rs:95-97`) with no dedup in `build_function_table` (`src/ast.rs:244-261`) — breaking "one record per function" on django, the decorator-dense corpus. **Resolution:** specify the data source (e.g. `LoadedRepo.files[*].functions()`), `kind_id`→string mapping, Evidence-vs-raw-array output, and a stated decorated-function dedup rule (in emission or as a §2.4 harness collapse rule).

7. **§2.4 — `start_line ±1` is the wrong matching primitive and fails systematically on the flagship corpus.** tree-sitter-rust's `function_item` excludes preceding doc comments/attributes (sibling nodes), while LSP `DocumentSymbol.range` includes them — every doc-commented Rust function (most public functions in this repo) offsets far past ±1, making M1's diff lists mostly matching noise. (Soundness's first-pass claim that this corrupts strata was self-retracted: §2.4 correctly derives strata oracle-side.) **Resolution:** match on the oracle's `selectionRange` (name token) by containment within prism's `[start_line, end_line]` plus name equality; this also subsumes the decorator offset in finding 6.

8. **§2.2/§2.9 — pyright's call-hierarchy support is an unverified precondition for one-third of measurement 2.** The prototype was Rust-only, and §2.2's quirk handling anticipates only per-position absence, not wholesale capability absence; if missing, django's M2 column is 100% `oracle_error`. **Resolution:** add a kickoff capability smoke-probe as a plan precondition with a named fallback (basedpyright, or `textDocument/references` + inventory containment — nearly free since caller-function-level matching already exists).

9. **§2.10/§2.1 — stale-SUT drift is recorded, never detected.** `prism --version` emits only `CARGO_PKG_VERSION` (`src/main.rs:36-40`), constant across dev commits; recording the repo's HEAD says nothing about what the binary was built from — the exact silent failure the lineage documents ("Stale-binary drift is silent," meta-analysis line 307). **Resolution:** bake `GIT_SHA` + dirty flag via `build.rs` (the `GRAMMAR_FINGERPRINT` mechanism already exists) and have the harness **fail or flag `sut_stale`** on mismatch, not merely record.

10. **§2.2/§4 — oracle failures can hollow out denominators while gates still pass, and G3 is entangled with live-oracle stability.** Errors are excluded from P/R denominators with no floor, and G3 ("two consecutive runs ⇒ identical raw metrics") flips on a single timeout difference with no harness bug present. **Resolution:** add minimum-successful-probes per corpus/stratum and a max `oracle_error_rate` (else baseline invalid); store per-probe oracle responses in the run JSON and define G3 as identical-samples-live + identical-metrics-under-replay (`--report-only` already exists), reporting live variance separately.

11. **§2.8 — adjudication keys collide and the seeded records are mis-keyed.** Keying by `(corpus, measurement, symbol, site)` omits seed identity, direction, and granularity; the seeded `mcp/tools.rs:157` is the caller-function start, while the actual call is line 162. **Resolution:** key by seed definition + call-site location + direction; fix the seeded records.

12. **§2.1/§2.2 — dataclass schemas and normalization rules are absent.** `FunctionDef`/`CallEdge`/`Location` need path form, URI conversion, 0-based LSP vs 1-based Prism lines, columns, range inclusivity, and tolerance tie-breaking (two candidates within ±1 has no rule). **Resolution:** add a schemas + normalization subsection; comparison code depends on it before anything else can be written.

13. **§2.5 — strata are neither disjoint nor mechanically classifiable.** `Q-scoped` overlaps `U-free`/`C-name` (in Go, virtually every cross-package call is Q-scoped), and "free function vs method" is language- and parent-context-dependent — tree-sitter node kinds alone don't decide it. Rigor rated this MAJOR, Soundness MINOR; **Rigor is right** — per-stratum metrics are the spec's primary deliverable, and overlapping strata double-count symbols and muddy cross-corpus comparison. **Resolution:** define exclusive assignment precedence (e.g. collision > Q-scoped > U) and the per-language classifier.

14. **§2.5 — direct-vs-transitive depth is not pinned.** LSP call hierarchy is direct; prism `--depth` defaults to 1 but traverses (`src/main.rs:250-267`). **Resolution:** require `--depth 1` explicitly unless a metric intentionally measures transitive closure.

15. **§3.1 — the common-module rewrite is wrong as written.** Current tests use `mod common; use common::*;` (93 files); `use crate::common;` alone breaks every unqualified helper call. **Resolution:** specify `use crate::common::*;` or a mechanical qualification rewrite.

16. **§2.1 vs §5 — the Python runtime contract contradicts itself.** §2.1 mandates uv-managed 3.12; §5 allows container pytest on ≥3.10. **Resolution:** pick one supported matrix (e.g. 3.12 required, container check verifies exactly that).

## MINOR

18. **§2.6 — "first occurrence outside string/comment" mislocates the identifier on binding lines** (`let target = edge.target();` resolves the LHS local → false confirmed-FP for a correct edge). Prefer call-position occurrences (followed by `(`, preceded by `.`/`::`), fall back to any-occurrence.
19. **§2.1 — `definition_at -> Location | None` under-models LSP** (0..n results: trait impls, interface methods). Make it `list[Location]` now with an M3 policy (TP if any matches).
20. **§2.2 — no escape trigger for the homegrown quiescence layer.** State one: if `$/progress` heuristics burn >~2 days, swap multilspy behind the `Oracle` seam.
21. **§6 vs §2.10 — Wilson 95% intervals are promised in risks but absent from the report schema.** Add the JSON/Markdown fields.
22. **§0 — baseline count mismatch:** spec says 121 targets (correct per current `Cargo.toml`); `s1-followups.md` says 123. Reconcile in the context doc.
