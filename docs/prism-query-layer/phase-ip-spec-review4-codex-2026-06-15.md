BLOCKER - §14 harness attribution is not buildable as written.  
The spec says add `"I-dispatch"` to `STRATA` and pre-check `classify` on `resolution_kind`, but `classify` receives only a `FunctionDef`, name counts, language, and package dirs ([eval/tier_a/strata.py](/Users/wesleyjinks/code/slicing/eval/tier_a/strata.py:27)). It runs before any Prism caller/callee evidence is collected ([eval/tier_a/cli.py](/Users/wesleyjinks/code/slicing/eval/tier_a/cli.py:500)). Current `CallEdge` has no resolution field ([eval/tier_a/model.py](/Users/wesleyjinks/code/slicing/eval/tier_a/model.py:36)), and `sut.py` ignores `Reason::Resolution` today ([eval/tier_a/sut.py](/Users/wesleyjinks/code/slicing/eval/tier_a/sut.py:78)).  
Fix: keep seed strata unchanged. Add per-site `resolution_kind`/`dispatch_kind` after SUT extraction, and make the precision gate filter the site diff set by that metadata. PR-2 exclusions need a separate AST/drop-telemetry source, because unrecovered receiver sites cannot be discovered from resolved `InterfaceDispatch` edges.

BLOCKER - §6 `canon_type(node)` cannot fail closed on Go type parameters without scope.  
The spec maps `type_identifier` / `qualified_type` to bare names, while also saying type parameters become `GoDispatchGap::Generic` ([spec](/Users/wesleyjinks/code/slicing/docs/superpowers/specs/2026-06-14-prism-phase-ip-type-confirmed-dispatch-design.md:168)). Tree-sitter represents declarations via `type_parameter_list`, but a use like `T` in a method signature is still just a type node/name; the current extractor reads `type_spec` name/type and not type parameters ([src/type_providers/go.rs](/Users/wesleyjinks/code/slicing/src/type_providers/go.rs:179)).  
Fix: define `canon_type(node, type_param_scope)` or declare any method/interface under a `type_parameter_list` non-dispatchable for PR-1.

MAJOR - §11 scoped full-repo dispatch states the goal but not the build API.  
Rev 4 now says `build_scoped` computes Go dispatch over the full repo and skips absent scoped targets. Current code cannot do that by adding fields: it filters files, then calls `CodePropertyGraph::build_enriched(&filtered)` ([src/cpg/context.rs](/Users/wesleyjinks/code/slicing/src/cpg/context.rs:167)), which builds the call graph from `filtered` ([src/cpg/build.rs](/Users/wesleyjinks/code/slicing/src/cpg/build.rs:136)).  
Fix: specify a new assembly path with full-repo `CallGraph`/dispatch maps but scoped node construction, including what Step-5b uses for callee source lookup.

MAJOR - §17’s CHA factual claim is still wrong.  
The spec says Go methods are absent from `virtual_method_nodes`; actual code indexes every function whose name matches a C++ virtual method, regardless of language/file ([src/cpg/build.rs](/Users/wesleyjinks/code/slicing/src/cpg/build.rs:534)). Skipping Go-owned Exact seeds is not sufficient; a C++ Exact seed with the same method name can still fan out to a Go function in the override index.  
Fix: filter both the seed scan and `virtual_method_nodes` candidates to C/C++ or to functions proven owned by the `TypeDatabase`.

MAJOR - §15’s gap contract contradicts admitted-match behavior.  
`CrossPackageOverApprox` is listed as a `GoDispatchGap`, and §15 says every gap is “recorded, never matched” ([spec](/Users/wesleyjinks/code/slicing/docs/superpowers/specs/2026-06-14-prism-phase-ip-type-confirmed-dispatch-design.md:391)). But §6 explicitly admits bare-name cross-package matches as measured over-approx ([spec](/Users/wesleyjinks/code/slicing/docs/superpowers/specs/2026-06-14-prism-phase-ip-type-confirmed-dispatch-design.md:182)), and §12 says non-local construction fallback still produces Exact edges.  
Fix: split fatal gaps from admitted telemetry counters, or make those cases fail closed.

“No bump because additive trailing `#[serde(default)]` fields” conflicts with the cache code comment. The safer rationale is GIT_SHA invalidation, deserialize-miss behavior, and `--no-cache` for dirty matrix/dev loops. Either bump to 9 or state that rationale explicitly.
