## Merged Spec Review — Prism S1 Perf Hardening + Level-4 Index Inversion

Both lenses verified the spec's load-bearing claims against the code (28 call sites, 8 hot sites, Step 5b first-match, `known_fn_names` fixed before Phase 3, `Tree: Send+Sync` in pinned tree-sitter 0.25.10) and agree the decomposition, layered correctness contract (§2), and A→B1→C sequencing are sound. The issues below are contract-precision defects, not design defects.

### BLOCKER

1. **§3 Slice A — `FunctionInfo` as specced cannot hold what the Functions query captures.** `name: String` cannot represent anonymous JS/TS callbacks, which the query captures and `all_functions()` must keep returning (`function_name` genuinely returns `None` for callback-position lambdas); and the struct stores no `kind`, yet the spec's own parity test is defined over "identical `(kind, byte-range)` sequences." An implementor is forced into an unspecified, semantics-affecting choice — drop unnamed nodes (changes the CPG node set, violating §2.2) or invent an `""` sentinel (leaks into Step 5b name matching) — inside a slice contracted to be byte-identical. **Resolution:** `name: Option<String>`, add a `kind` field, require the table to preserve the full captured sequence in query order, and note that JS/TS name inference reads *parent* nodes, so table construction cannot be reordered before tree construction. *(Disagreement: Rigor=BLOCKER, Soundness=MINOR. Rigor is right on severity — the unrepresentable case forces an undocumented choice that touches the §2.2/§2.3 gates; Soundness is right on mechanism — the risk is dropped nodes/sentinel leakage, not wrong-node reconstruction, since no concrete parent/child exact-byte-range ambiguity exists.)*

### MAJOR

2. **§3 Slice A — reconstruction contract underspecified.** "`descendant_for_byte_range` followed by kind/range walk-down check" doesn't say what the check compares against (resolved by the `kind` field above) or what happens on failure: panic in debug, fall back to direct query/manual walk, or skip. Two compliant implementations could pass parity tests while one silently drops nodes. **Resolution:** specify failure behavior explicitly (recommend: fall back to the direct query path, never silently skip).

3. **§4 B1 — "identical pattern semantics" hides verified order-dependent quirks a clean scanner will silently fix.** The legacy `find(arrow).or_else(find(dot))` gives `->field` *anywhere in the remaining line* priority over a closer `.field` (so `s.cb = f; t->cb = g;` returns only `{g}`), and a non-assignment substring occurrence (`->cbx` matching `find("->cb")`) consumes scan position and suppresses a real earlier assignment entirely. Add the remaining quirks: single-`=` anchoring, RHS token stop rules, `&` stripping, `known_fns` filter, per-file `BTreeSet` dedup/sort, per-line state reset. A natural generalized scanner returns strictly more edges — a byte-golden break inside a perf commit, exactly what §2.4 forbids. **Resolution:** document these quirks as the *definition* of "identical pattern semantics" and pin them with mixed-accessor and prefix-overlap fixtures in the corpus.

4. **§4 B1 — the differential oracle's field universe is undefined, which can make the proof vacuous.** If fields are enumerated from the new index's keys, any field the generalized scanner fails to extract at all produces no key, the legacy oracle is never consulted, and the miss is structurally invisible — and §2.2's entire B1 correctness argument rests on this test. **Resolution:** specify an index-independent universe — every unresolved, qualifier-bearing, alphanumeric callee name Phase 3 would actually query (`call_graph.rs:315-327`), plus every identifier appearing after `.`/`->` in corpus sources, plus explicit negative fixtures — and assert equality in both directions. With finding 3's fixtures in the corpus, quirk divergence becomes a failing test rather than a silent behavior change; these two fixes together are what make "byte-identical" trustworthy.

5. **§5 C1 — the loader contract changes skip *classification*, not just order.** Today the loader reads and UTF-8-decodes *before* unsupported-language detection; the spec moves "unsupported" into the pre-read walk, flipping a non-UTF-8 file with an unsupported extension from `NotUtf8` to `Unsupported`. The spec's skip-rule list also omits `NotUtf8` entirely; whether `fs::read` happens walk-side or par-map-side is unspecified; "walk order" is raw `read_dir` order, not canonical; and collect-then-append reorders `skipped` relative to the serial loader despite the "exactly" promise. **Resolution:** specify the candidate record (`(rel_path, source, language)` produced in the current read→UTF-8→language order), where hashing occurs, and that parse-failure entries splice back into walk-position slots; either preserve raw serial order for serial-vs-parallel parity only, or sort entries and document the change. *(Disagreement: Rigor=MAJOR, Soundness=MINOR. Rigor is right — beyond ordering, the classification flip is a real result change and trips the spec's own §2.1 equality test; Soundness's verified unobservability through current consumers scopes the fix to spec text rather than design.)*

6. **§2/§5/§7 — graph-equality contract conflicts with cache insertion-order stability under the no-`CACHE_VERSION`-bump rule.** The binary cache serializes node/edge vectors in insertion order to preserve `NodeIndex` stability, while the C tests assert only *sorted* equality. If C2's "deterministic merge" doesn't reproduce serial insertion order, cached bytes change with no version bump. **Resolution:** require parallel assembly to reproduce serial insertion order (and test exact order, not sorted), or declare sorted-canonical equality contractual and justify why cache bytes cannot drift. (Rigor only; verified against `cpg_cache.rs`.)

7. **§7 — acceptance gates are not objectively reviewable.** "No longer shows in top stacks" and "uses >1 core" need commands, target repos/inputs, sample duration, a top-N or percentage threshold, and build-profile/cache settings. **Resolution:** specify the exact profiling invocation and threshold per gate.

### MINOR

8. **§3 Slice A — the eager table must reuse `all_functions()`'s dual path** (query when compiled, `collect_functions_manual` otherwise). All 11 languages have working queries today and a dual-path consistency test exists, but the fallback is load-bearing against caret-ranged grammar drift (the same drift `GRAMMAR_FINGERPRINT` exists for). **Resolution:** one sentence — "build the table via the existing dual-path logic." *(Disagreement: Rigor=MAJOR, Soundness=MINOR. Soundness is right — the fallback fires only on runtime compile failure no language currently hits; a one-sentence plan clarification suffices.)*

9. **§3/§7 — eager table cost lands on the warm nav path, and nothing watches it.** On a nav-cache hit the CPG build (and all `all_functions()` calls) is skipped, but `load_repo` still parses every file — so eager construction adds per-file query+extraction cost to a ~0.45s warm path that currently pays nothing for function tables. "Always pays for itself" is argued from the cold path only. **Resolution:** add warm-time parity (no material regression) to the bench-ladder report-out.

10. **§4 B1 — the rejected simpler alternative (per-field memoization) is unrecorded.** Caching legacy results per distinct field is a few lines and trivially byte-identical, but stays O(distinct_fields × total_lines) — likely insufficient at Go scale per the profiling evidence. The decision is probably right; the spec never says why. **Resolution:** one paragraph of rationale, since the generalized scanner carrying findings 3–4's risk is scaffolding B2 is contracted to delete.

11. **§4 B2 — provenance has no in-memory home.** Evidence reasons currently have no assignment-site variant, and "no wire change" leaves the recorded `file:line` nowhere to live. **Resolution:** define the temporary type/field and its lifetime, or explicitly defer the shape to the B2 plan.

12. **§6/§7 — bench-ladder needs a usage contract and a pinned repo list.** Specify repo-list format, cache-dir behavior, LOC counting, timeout exit semantics, RSS mechanism, warm-run definition, and an example output row — and pin the default list to include django and rust-analyzer, the two motivating timeout failures, so the mandated PR re-run actually answers "did S1 restore the scale ladder."

**Verdict:** Not ready to plan as written — revise §3's `FunctionInfo` contract (BLOCKER 1 + MAJOR 2), pin §4 B1's legacy quirks with an index-independent oracle universe (MAJORs 3–4), and fix §5 C1's skip-classification/ordering and the cache-order contract (MAJORs 5–6); the design and decomposition themselves are sound and the remaining items are one-sentence plan clarifications.
