# Merged Spec Review — Tier-A Accuracy Harness + Dev-Loop Test-Time Reduction (rev 2)

Both lenses returned full reviews; nothing is missing. Both independently confirm rev 2 is unusually well-grounded: the 121-target count, the §3.1 migration table, the 93 common-header files, the pinned-probe locations, and the wire-format extraction table all verified against the repo. The disagreements below are resolved inline.

## BLOCKER

**1. §2.2 / §2.5 / G4 — Validity floors conflict with expected undersized strata.** The spec predicts Go `U-free` will "run short," but §2.2 marks any stratum with fewer than 6 successful probes `baseline_invalid`, and G4 requires floor-valid baselines — so an expected, documented corpus shape fails the gate. *Resolution:* define whether naturally undersized strata are skipped, reported-but-non-gating, or corpus-invalidating; "non-gating with recorded shortfall" matches the spec's existing honesty posture.

**2. §2.5 — SUT errors can hollow out the metrics.** `sut_error` probes are excluded from P/R denominators, but validity floors cover only oracle errors. A broken prism build that errors on hard probes would report inflated P/R and still pass gates. *Resolution:* add a SUT-error floor symmetric to the oracle one, or count SUT errors as FNs for recall plus a separate gated failure rate.

## MAJOR

**3. §2.4 / §2.5 / G3 — Live sample identity is hostage to the oracle variance G3 claims to be decoupled from.** The sample derives from the live oracle inventory; one `documentSymbol` timeout (an expected, ungated `oracle_error` per §2.2) shifts collision stats → strata → sample, failing G3's "identical samples across two live runs" clause for a reason the spec explicitly says should not gate. *Resolution:* persist the inventory snapshot keyed by corpus SHA (the run JSON already stores per-probe raw responses) and define the sample as a function of `(snapshot, seed)`; or narrow G3's identity clause to replay and report live sample drift ungated.

**4. §2.6 — Measurement 3 mints "confirmed FP" where the oracle is structurally ambiguous, and its mechanics break on renamed call tokens.** Three compounding facets: (a) the auto-confirm path contradicts §0's own core contract ("diffs are adjudicated, not auto-failed") — `textDocument/definition` at a method call can legitimately return the trait/interface declaration while prism resolved a concrete impl, turning defensible edges into confirmed FPs, with the bias concentrated on exactly the method strata S3 exists to measure; (b) the find-the-seed-name-on-the-line heuristic fails on aliases (`from m import f as g`), constructors, and re-exports — and `nav callers` currently drops `callee_name`/`qualifier` when rendering `CalledBy`, so this is a real current-surface limitation; (c) `definitions_at()` returns only `Location` while §2.6 requires name-aware matching. *Resolution:* route M3 mismatches through the adjudication store (its key schema already accommodates `measurement: "m3"`), defaulting declaration-returned cases to `ambiguous` and reporting confirmed vs adjudicated separately — the petgraph-`.target()` class still auto-confirms; enrich the definition target beyond bare `Location`; explicitly exclude or flag alias/rename cases. 

**5. §2.3 / §2.9 / B2 contract — B2's Python regression signal has no reliable live carrier.** The only live Python signal is pyright-on-django (the acknowledged worst case, with a 25% floor that may render it `baseline_invalid`); the §2.3 innermost-only dedup rule deliberately blinds `nav functions` — hence Measurement 1 — to the decorator double-capture quirk both before and after B2 fixes it; the quirk's only live trace is M2-on-django edge noise (the CPG's `(file, name)`-keyed `func_index` silently strips edges from one of each wrapper/inner pair). *Resolution:* explicitly designate the §2.7 decorator-wrapped-fn matrix case as B2's flip indicator; add one small static Python corpus (flask or click) where pyright noise plausibly clears the floor; add a §2.9 sentence warning adjudicators that django M2 diffs partially reflect the dedup quirk itself.

**6. §2.5 / §2.8 — Edge identity is line-only and ambiguous.** `CallEdge.call_site` and adjudication keys are file:line; current `CallSite` has no column and its ordering collapses same-caller/callee/line duplicates, so same-line multi-call sites are uncountable. *Resolution:* define site-level counting as a multiset, add call-token/column or `other_def` to the identity, or explicitly exclude same-line multi-call sites with a recorded count.

**7. §2.8 / §4 G1 — Corrected-metric math needs a truth table, and G1's semantics are underdefined.** The spec names verdicts and broad behavior but not the legal direction×verdict combinations, exact TP/FP/FN transforms, Wilson denominators, stale handling, or pending exclusion per metric. G1(a) also doesn't say whether P/R ≥ 0.95 is per direction, pooled callers+callees, per stratum, or pooled strata; and G1(b)'s hard-coded "raw P ≤ 0.2 and R ≤ 0.2" is an inverted gate — any incidental resolution improvement landing before the baseline run fails *harness* acceptance. *Resolution:* add a raw-class + verdict → metric-contribution table; pin G1's aggregation level; rephrase G1(b) using the matrix's existing `known_fail` idiom (reproduce the verdict *or* surface a flip-candidate report).

**8. §2.3 / §2.11 — SUT binary discovery and freshness mechanics are incomplete.** The runner never says how `PrismCli` finds the binary (PATH, `target/release/prism`, env, flag) or that the harness builds it; and without `build.rs` rerun triggers on `.git/HEAD`/refs/dirty-state, the embedded `GIT_SHA` can itself go stale, defeating the `sut_stale` check. *Resolution:* add `--sut-bin` with a documented default resolution order and build instructions; specify `cargo:rerun-if-changed` triggers for the git-state inputs.

**9. §3.1 — Umbrella module naming is ambiguous.** The invocation example requires `cargo test --test algo_taxonomy taint_cve::`, but plain `mod taint_cve_test;` exposes `taint_cve_test::`. *Resolution:* require `#[path = "taint_cve_test.rs"] mod taint_cve;` in umbrella `main.rs` files, or change the invocation examples to match the file-derived module names.

## MINOR

**10. §2.1 / §2.5 — `FunctionDef` schema vs stratifier contradiction.** Rigor rated this BLOCKER; Soundness's deeper verification is right and it lands MINOR: `U-method` needs only `kind` (present, from the oracle side), Go/Python `Q-scoped` and Rust's non-crate-root clause are path-derivable, and the only un-derivable case is Rust inline `mod` inside crate-root files (rare). The spec-internal contradiction is still real — §2.5 cites "inventory container info" that the pinned `FunctionDef` lacks and §2.1's boundary rule forbids reaching back for. *Resolution:* add `container: str | None` to `FunctionDef` (or drop the inline-`mod` clause and define Rust `Q-scoped` purely on paths); while touching the schema, adopt Rigor's `semantic_kind`/optional `raw_kind` split and state that SUT-side kind is informational only — tree-sitter's `function_item` makes method-vs-function unmappable for Rust on the prism side.

**11. §2.5 — Caller-function-level granularity has no rule for call sites outside any inventoried function.** Python module-level calls (django has many) silently drop from the coarser metric, and LSP call-hierarchy behavior at module scope varies by server. *Resolution:* define a `module_level` pseudo-container bucket and count it explicitly.

**12. §2.10 / G4 — "Adjudicated" baseline has no bounded adjudication budget.** The prototype saw ~62 sites from one seed; django diffs could run to hundreds of items of unbounded human work on the S3/B2 critical path. *Resolution:* define baseline-sufficient adjudication (e.g., all Rust/Go diffs plus a fixed-size django sample, remainder pending).

**13. §3.1 — WP2 silently changes the concurrency topology.** Up to 16 files' tests will share one process and thread pool where they never did before; verified hygiene (no `set_var`/`set_current_dir`, tempfile-isolated caches) mostly covers it, but G6's single green run won't catch intermittent cross-file interference. *Resolution:* one sentence in §3.1 — G6 runs the consolidated suite 2–3×.

**14. §3.1 — Coverage-matrix wording should distinguish consumers.** A fourth matrix consumer exists (`coverage_test.rs:987`) but consumes `coverage/matrix.json`, not a hardcoded path list; the three path lists are at lines 106, 325, 472. *Resolution:* rephrase as "three path lists plus one matrix algorithm-completeness consumer."

**15. §3.3 — Timing protocol needs exact command semantics.** *Resolution:* pin the timer (`/usr/bin/time -p` or equivalent), the captured fields, and whether P2 runs immediately on P1's warmed state.

## Verdict disagreement, resolved

Rigor says "needs changes"; Soundness says "sound to plan." Both are right at their own altitude: the architecture — two hard seams, four complementary measurements, adjudication-not-auto-fail, pinned probes, validity floors, replay determinism — is sound and nothing here justifies re-architecting; but the spec text has two gate-logic blockers and several ambiguities an implementor cannot resolve alone.

**Verdict: not ready to plan as-is — fold a rev 3 addressing BLOCKERs 1–2 and MAJORs 3–9 (all local, additive deltas); the architecture itself needs no rework, and planning can start immediately after rev 3.**
