## Mechanism (the pipeline, stage by stage)

**M1. Export facts are collected per file** in `ParsedFile::extract_js_ts_export_facts` (READ `src/ast.rs:2395-2480`).
The `export_statement` handler (`src/ast.rs:2738-2893`) has four arms:
- export lists record `Local(name)` with **no check on what `name` is** (`:2780-2808`);
- `export default <identifier>` records the same `Local(name)` (`:2812-2831`);
- function declarations record `Local(fn name)`;
- the `lexical_declaration | variable_declaration` arm (`:2861-2893`) records `Local(declarator name)` only when the
  initializer is `arrow_function` or `function_expression`. Anything else increments `skipped_expr_count`.

The facts are serialized into the CPG cache (READ `src/cpg_cache.rs:89`).

**M2. F4 provenance.** The skip came from P4 (#156, commit `2b58aa5d`) as its "F4 fix" (codex MAJOR 2). The commit
message reads: "`export const f = cond ? a : b` recorded a fact keyed on the declarator's own name regardless of its
initializer, so if any same-file FunctionId named `f` existed elsewhere (e.g. a nested function), R4c could bind the
export to the wrong function." The fix kept only the "1c forms" of the P4 spec, `export const f = (...) => {...}` and
`export const f = function(...) {...}`
(`docs/superpowers/specs/2026-07-03-prism-p4-js-export-modeling-spec.md`, item 1c). The pinned test is
`exported_const_ternary_does_not_resolve_to_nested_same_name_function`. **The reasoning to preserve:** a fact names a
string, and R4c turns that string into callables by name lookup. So a fact is only as safe as the guarantee that the
name denotes the export's own function.

**M3. R4c resolves by name** (READ `src/resolution.rs:3358-3435`, `:3654-3680`). An eligible `MemberImport` binding
resolves the module path with `resolve_js_ts_relative_module`, which accepts relative paths only (READ
`src/call_graph.rs:6426-6490`). It then looks up `js_ts_resolved_exports[file][member]` and takes
`self.functions.get(local_name)`, filtered to that file and to non-methods. The outcome is:
- exactly 1 match: `Exact` `import_member`;
- more than 1: demoted `NameOnly`;
- 0: `drop(UnknownName)`. In JS/TS there is never a fallback to R5.

Shadowed importer locals are refused (`js_ts_function_locals`). Re-export chains are depth ≤ 2, and a duplicate name
poisons the export (READ `src/js_exports.rs:229-373`).

**M4. The callable identity of a wrapped arrow.** Pattern 3 of `Language::function_name` (READ
`src/languages/mod.rs:1171-1183`) gives an arrow or function expression the declarator's name when the function is
**any direct argument of a call whose parent is the `variable_declarator`**. It does not check the callee or the
argument position. Function expressions with their own name keep that name (`:1207`). MEASURED P3 function
inventories:
- `export const Island = forwardRef<…>((props, ref) => …)` registers `Island@2-4` (C02);
- `create((set) => …)` registers `useStore` (C13);
- `createSelector(a, (x) => …)` registers `selectA` (C24);
- `memo(forwardRef(fn))` (C08) and `forwardRef(fn) as any` (C25) register a function with `name: null`.

**M5. Anonymous functions own no call sites.** They never enter `functions` (READ `src/call_graph.rs:1272`). Phase 2
skips them with `None => continue` (`src/call_graph.rs:1337-1340`). MEASURED P14: X `Sidebar.tsx:214`
(`<SidebarInner …/>`) has no call-site row, because its enclosing arrow (163-215, inside
`Object.assign(forwardRef(fn), …)`) is anonymous. This is the "unowned" lane.

**M6. JSX elements are call sites** in `.js/.jsx/.mjs/.cjs` and `.tsx` only (READ `src/queries.rs:150-163`; the
`.ts` query has no JSX). The callee is the tag's identifier, or the property of a member tag (READ
`src/languages/mod.rs:709-724`). JSX has no argument list, so a new JSX edge adds no Step-5b argument→parameter
DataFlow. MEASURED P11: the X `dfg-stats` counters and the full `--edges` dump (60,163 lines, SHA `0653ceb9…`) are
**byte-identical** between base and prototype. MEASURED P6: all 111 new edges on X+F are JSX sites.

**M7. Prism already binds wrapped components by this identity through other routes:**
- same-file `<Island/>` resolves `Exact local_def` to the inner arrow (MEASURED P3 C03);
- `const Island = forwardRef(fn); export { Island }` and `export default Island` resolve `Exact import_member` to
  the inner arrow (MEASURED P3 C04, C05);
- live edges of this kind already exist on the corpora: X 1, F 2 (MEASURED P5).

The gap is specific to the declarator-export arm.

**M8. A pre-existing F4-class bypass exists.** MEASURED P3 C06: `const f = a > 0 ? a : b; export { f };` next to a
nested `function f` inside `outer` resolves `app.ts → util.ts:f@2-2` as **Exact import_member**, which is a false
Exact on `main`. The list and default-identifier arms never received the F4 guard. Prevalence: 0 of 2,409 (X),
156 (F), and 46 (R) Exact `import_member` edges target a function nested in another function (MEASURED P5). A related
pre-existing case: `export let A = () => …; A = Other;` still resolves Exact (MEASURED P3 C21). Both are outside this
slice (SPEC §0 D4).

**M9. `skipped_expr_count` is surfaced as one lump.** Per-file `JsExportFacts.skipped_expr_count` is summed into
call-stats `js_export_skipped_exprs` (READ `src/navigation/queries.rs:626-636`). The sum mixes declarator skips with
default-export and CommonJS skips. MEASURED P1: X 637, F 389, R 28, T 184.

**M10. Import provenance mechanics.** JS default and namespace import bindings are extracted with `eligible: false`,
and eligibility is decided later (READ `src/ast.rs:2244-2257`). MEASURED P6a-debug: the first prototype required
`eligible` for `React.forwardRef` and refused C15, C26 and C27. The fix was to check "not written"
(`js_ts_module_value_written`, `src/ast.rs:4613`), which treats `X.displayName = …` as a non-write (READ: the
binding-pattern collector `:4971` ignores `member_expression`). **r2:** that same blindness to member writes is what
let sol's W1 through (`React.forwardRef = fake`, C28). r2 adds occurrence custody (M14; SPEC §3.2). The benign
reading for `Island.displayName` is MEASURED Exact in C38.

**M11. Other consumers.**
- The nav copy of R4c name-correlation (READ `src/navigation/call_resolve.rs:30-75`) compares
  `resolved.local_name == target_name`, then re-resolves. It stays consistent if `local_name` is the inner
  function's registered name. MEASURED P12: `nav callers --symbol Island --file …/Island.tsx` returns 0 items on
  base and 11 on the prototype.
- `ImportForward` needs `forwardable_function_locals`, which holds function declarations only (READ
  `src/js_exports.rs:307-315`, `src/ast/js_module_forwarding.rs:38-74`). A wrapped export forwarded through
  `import {X}; export {X}` therefore stays refused (fail-closed).

**M12. Cache versions.** `CACHE_VERSION = 97` (`src/cpg_cache.rs:217`, pin test `:755-757`).
`NAV_CALL_EDGE_CACHE_VERSION = 53` (`src/navigation/call_edge_cache.rs:97`, pin `:716`). P4 bumped both when it
changed export facts.

## Round 2 (after sol spec round 1)

**M13. There is no JSX-vs-call distinction in the call-site model** (READ). `CallKind` is `{Call, MacroInvocation}`
(`src/call_graph.rs:390-394`). `call_kind_at` returns `Call` for all non-Rust languages (`:5504-5507`). `CallSite`
has no site-kind field (`:420-496`). JSX rows dump as `"call_kind":"Call"` (P1). `new_expression` is not captured by
the JS, TS or TSX call queries (`src/queries.rs:150-163`), so `new X()` is not a call site (MEASURED C32).

**M14. Precedent for module-object custody** (READ). The CJS producer barrier is refusal-only occurrence custody over
`module`/`exports`: it admits exact occurrences, and it revokes on aliases, escapes, reflective, computed or nested
writes, and `eval`/`with` (`src/ast/js_cjs_export_barriers.rs:1-60,125-158`). Its plan states "Cross-module mutation
and require-time consumer snapshots remain open" (`docs/superpowers/plans/2026-09-11-cjs-export-barriers.md:24`).
SPEC §3.2 applies the same model to `"react"` default and namespace bindings.

**M15. Named imports share the object under CJS interop** (READ, ASSUMPTION about bundlers). With CJS React, a named
import compiles to a property read on the same module object, so a same-file default-object write affects it.
Control C37 is refused under both D6 options.

## Not measured, and why

- **Recall of the latent lane.** The latent projection is not validated by a prototype; building a `paths` resolver
  is out of scope. It is an upper-bound projection.
