## Small output contract

Schema `prism.parameter-syntax-frequency/1`, `authorizes_runtime_edge:false`, `measurement:"compiler_syntax_only"`. Top level includes compiler version/hash, manifest hash/source identity, files, and frequency tables. No timestamp/process IDs inside canonical data; volatile timings stay in receipt. Canonical output uses fixed field insertion order, arrays sorted by file path then numeric start/end/ordinal, UTF8/code-point lexical ordering, never localeCompare. One trailing newline. No hashed per-row IDs or generic graph schema.

Each file carries path/hash/bytes, script kind, declaration_only/test_path booleans, parse diagnostics, excluded_bodyless_signature_count, and nested callable rows. Each callable carries exact SyntaxKind name, UTF8 token start/end, `arrow_parenthesized` boolean or null, and ordered parameters. Each parameter carries raw ordinal, whole-parameter UTF8 token span, binding-name/pattern UTF8 token span, pattern `identifier|object|array|other`, and booleans optional/rest/outer_initializer/nested_pattern/nested_default. Tuple `(file,callable token start,end,parameter ordinal)` addresses a row; exact duplicate tuples are an invariant error, not silently deduplicated. No owner/name inference is needed.

Diagnostics retain code, original optional start/length and converted byte span when available; unavailable diagnostic coordinates are null. Files with syntax diagnostics are still scanned and included in diagnostic-tagged counts, never relabeled clean. Tool/schema/worker errors fail the run; syntax diagnostics are ordinary recorded observations. All414valid-manifest files get a row, including empty files and declarations. No parser exception becomes a zero-count file.

## Exact discovery/classification rules

Observe only TypeScript nodes of these kinds **with a body**: FunctionDeclaration, FunctionExpression, ArrowFunction, MethodDeclaration, Constructor, GetAccessor, SetAccessor. These are body-bearing syntax, not asserted runtime callables. Node traversal visits each AST node once via `forEachChild`, including nested bodies/initializers; do not use Prism inventory. Count bodyless nodes in that same list plus MethodSignature, CallSignature, ConstructSignature, FunctionType and ConstructorType in `excluded_bodyless_signature_count`, without parameter-frequency rows. Declarations remain a separate file stratum even if malformed/ambient source contains a body. Index/property signatures are not callable parameter rows; traverse them to find nested excluded function-type nodes.

Arrow form uses `arrow.getChildren(sourceFile)`, not `forEachChild`: require a **direct** OpenParenToken child before `arrow.equalsGreaterThanToken` around the parameter list. Do not use a string prefix or parentheses in the body/type subtree; cover bare/parenthesized/async/generic arrows and parenthesized arrow bodies. Omit bound/anonymous owner classification entirely.

Parameter pattern comes directly from `parameter.name`: Identifier/ObjectBindingPattern/ArrayBindingPattern/other. Optional=`questionToken`, rest=`dotDotDotToken`, outer_initializer=`initializer` presence. Nested flags traverse **binding pattern names only**: a strict descendant object/array binding gives nested_pattern; a nested BindingElement with an initializer gives nested_default. Never search the initializer expression or type annotation for nested binding/default evidence. One destructured pattern is one parameter regardless of leaf count.

Token starts use `node.getStart(sourceFile,false)` and node.end; preserve the whole parameter versus its binding node separately. No raw/full `pos` field or cross-parser normalization is required. Decode UTF8 strictly while preserving BOM. Convert UTF16 boundaries through a precomputed source code-unit→UTF8-byte map (linear construction), refusing boundaries inside a surrogate pair; do not repeatedly rescan entire source for every span. Only UTF8 coordinates are serialized; UTF16 positions are internal inputs to the tested mapping helper. Tests assert BMP, astral, BOM, comments and CRLF exact offsets.

## Counts that can answer the question

Frequency tables use disjoint keys `(script_kind,declaration_only,test_path,parse_state)` where parse_state is `clean` or `syntax_diagnostics`. Report files, body-bearing callables, parameters, object-pattern parameters, array-pattern parameters, nested-pattern/default parameters, rest parameters, parenthesized arrows, unparenthesized arrows, and **destructured parameters before any later optional identifier in the same callable**. Also report the number of unique callables containing that last relationship. A parameter contributes once to that predicate, not once per later optional parameter. An optional identifier means identifier pattern+questionToken, independent of type annotation spelling. Keep rest and object/array dimensions separate; overlapping predicates have no combined numerator.

Counter derivation is explicit: file coverage comes from file rows; diagnostic counts come from each file’s diagnostics array; callable/parameter/cohort frequency counts come from emitted nested callable/parameter rows. `excluded_bodyless_signature_count` is the separate per-file tally from the exact exclusion traversal above, not a count derived from absent emitted callable rows; any aggregate of it sums those per-file tallies. Its independent oracle re-walks the fixed source or asserts the exact fixture exclusion count. Diagnostic-tagged observations never enter clean counters. Declaration files never enter nondeclaration counters. Sum group file counts to414 and reconcile each remaining field against its declared basis. The readout reports observed frequencies and coverage/diagnostics, not `supported`, `constructible`, `zero demand`, semantic validity or production readiness. A zero count in diagnostic-bearing coverage is explicitly only zero observed syntax, not proof of absence.
