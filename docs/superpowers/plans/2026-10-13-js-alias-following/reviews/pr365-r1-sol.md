R1. **WRONG · MATERIAL — direct calls of React memo objects have false truth.** Confidence: 99/100.

Evidence: `generator/variants.cjs:116–122`; `fixtures.jsonl:412`, id `local.react-memo.fn.call.trap.ts`, imports `memo` from React, declares `const decoy = memo(imp)`, then calls `decoy(1)`. React's [versioned memo implementation](https://raw.githubusercontent.com/facebook/react/v19.2.0/packages/react/src/ReactMemo.js) constructs and returns an object, with no call capability. That marked ordinary call cannot call `imp`: it throws a TypeError. An exact edge to `callee.ts:f` would instead receive `CORRECT` and be blessed as an improvement. This is a call-form error, independent of the question about grading a wrapped JSX render target. It involves no runtime mutation.

Recommended fix: author `none` for the direct-call forms and update their pins; retain the JSX forms separately. Alternative: remove the direct-call forms, at the cost of losing useful negative wrapper coverage. This does not apply to JSX, `useCallback` returning its argument, or an explicitly documented fictional wrapper API in place of React. An owner decision to model direct memo calls as synthetic render edges would require changing the stated truth contract, rather than treating this as JS callee truth.

R3. **WRONG · MATERIAL — different callable identities can be graded CORRECT, bypassing the verdict guard.** Confidence: 100/100.

Evidence: `js_alias_matrix_common.rs:132–134`, `run.cjs:106–114`, and `export.cjs:12–13`. A match is same file AND (same name OR same line). The generator also chooses the first declaration with that name. Two ordinary constructible inputs are:

```js
function f() { return "outer"; }       // line 1
function caller() {
  function f() { return "inner"; }     // line 3
  const h = f;
  return h();
}
```

The correct target is line 3. A reported exact target `caller.js:f` at line 1 also matches a Rust truth target explicitly specifying line 3. Likewise, with `function f() {} function g() {}` on the same line, a truth for `f` accepts an exact target for `g`. The scratch probe executes the actual reference matcher/verdict functions: both inputs produce `right: CORRECT, wrong: CORRECT`. Rust uses the same Boolean condition; its test at `js_alias_matrix_common.rs:519–523` expressly endorses name-independent line matching. A target change is still reported by full-row comparison, but CORRECT→CORRECT needs no acceptance entry, so an incorrect target can be blessed as correct. The reference and the port share this defect; it is not a port discrepancy.

Recommended fix: identify authored callables by file, registered name, and declaration span, with explicit declaration markers for duplicate names; make ambiguous identities an input error. Update both reference and Rust, and test wrong same-name/different-line and wrong different-name/same-line targets. Alternative: forbid duplicate names and multiple callable declarations per line, validating that restriction before grading; cheaper, but excludes ordinary nested JS and weakens upcoming shadowing coverage. This does not affect existing fixtures whose callable names and declaration lines uniquely distinguish all candidates. The current corpus passes; the demonstrated wrong grading is on valid synthetic inputs, not a claim of an already-observed product regression.
