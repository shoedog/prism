## Hypothesis / probe / result

Hypothesis: declared package directories could fit resource limits but still
depend on parent configuration/sibling source. Alternative: package configs are
self-contained and exclude all outside dependencies. Read package extends/paths
and observe actual configured roots/Program membership; this discriminates them.
Result: all six package configs inherit the parent; five observed Programs reach
sibling source. Math has 16 configured roots but 805 Program files. Fractional-
indexing has no sibling repository source but still 216 dependency files. The
self-contained alternative is falsified by actual compiler membership and config
dependencies, not directory sizes. No configuration rewriting.

Hypothesis: choosing a child config alone narrows the existing owner input census.
Alternative: the loader still indexes the complete supplied root. Replay root
versus child config against that same root. Result: both report 628 files and
input_budget; the narrowing hypothesis is false. Separately rerooted math fails
semantic_closure; its observer reports invalid_config. Rerooted editor fails the
earlier parse_error gate. These are controls on unchanged code, not regressions.

The private default observer returned budget_exceeded without usable membership.
That is not evidence of an empty Program or any specific resource mechanism. Its
native mixed-language refusal remains independently measured; no expanded retry.

Observer-suite setup hypothesis: the five file-level failures arise from missing
PRISM_CALLABLE_PROFILES rather than changed behavior. All five explicitly require
that variable before tests; supply it alongside the pinned compiler. Result:
694 passed, zero failures/skips. The incomplete 586-pass/5-file-failure setup run
is retained, not counted as behavioral RED or an attributed regression.

Prism callers lookup for acquisition::reproduce returned SymbolNotFound. Direct
source inspection and compiler/loader evidence substitute for unavailable graph
coverage; this does not prove absence of callers.

## Next increment: membership observations, not input selection

Proposed bounded contract; this slice does not implement it or make it authority.
Reuse the existing immutable audit root and compiler snapshot. A logical project
identifier is the selected config identity plus its complete observed inheritance
chain/effective compiler options and snapshot epoch, never a directory name alone.
Do not add a selectable installed profile to Rust ownership as a side effect.

Record distinct canonical sets with bytes/hash identity:

- A: full audited filesystem/config/dependency/link inventory, retaining existing
  traversal refusals and resource ceilings.
- R: configured roots from the compiler's existing config parser, not a second
  glob implementation. Preserve include/exclude/extends source provenance; reject
  unsupported/ambiguous selection syntax rather than infer membership authority.
- P: complete Program source-file membership, including imported excluded files,
  ambient declarations, dependencies, JSON, compiler libraries and unsupported
  source suffixes. Root membership is a separate flag, not an exclusive domain.
- L: actual native Prism loader census and skipped-reason ledger for the unchanged
  audit root; a package-directory census is comparison data, not a replacement L.
- D: descriptive domains of P (repository, dependency, compiler), with declaration,
  JSON, parser-supported and link-origin facets. A path partition is an observation
  only: dependency package identity and body authority require later proofs.
- Differences R/P/L, preserving every member and negative lookup/effect obligation.
  No set intersection may silently become the proposed executable input map.

First implementation must be a separate non-authorizing observation artifact,
with no runtime consumer and authorizes_runtime_edge=false. Empty/unverified,
oversize or partial acquisition produces an explicit unavailable observation,
never a complete zero-member set. Do not enlarge packet/heap/time/file budgets.
Bind all domains to the same reproduced snapshot, config chain, compiler and
producer identity. Require deterministic complete partitions without duplicate,
missing or cross-domain IDs. Use the real compiler's Program/host evidence for
membership; do not use resolved type names or compiler success as executable proof.

Later production design must separately decide which P domains Prism can represent
and prove byte-identical correspondence for every selected executable body while
retaining all other P/A members for closure and indexed-effect checks. It must not
weaken current duplicate/write/cache, ambient, unresolved-reference or epoch gates.
The existing full-census equality and budgets remain binding until that separately
reviewed contract exists. Known JSON/.mts and parser-error cases need source-backed
classification before choosing representations or claiming an existing defect.

## Required fixture matrix before expansion

These are executable fixture **requirements for the next implementation**, not
tests claimed to have run in this documentation slice. Every refusal must assert
no authority/edge; every observational positive must retain incomplete closure if
any independent obligation is unresolved.

| Case | Required observation / negative control |
|---|---|
| Direct contextual TS/TSX fixture, valid inherited config | Exact roots, Program, native census and config bytes in one epoch; body eligibility remains separate |
| Parent config and sibling alias inside A | Parent/sibling retained even outside the package; moving parent outside A refuses provenance |
| Excluded file imported by an included root | File is in P despite exclude; changing a declaration there invalidates the epoch |
| Native file outside configured/Program sets | Difference retained with source/skip evidence; cannot be silently dropped to satisfy equality |
| Automatic/configured/source type or lib entry | Dependency/compiler domains retained; unresolved entry and react-scripts still block closure |
| Same-named local and dependency declarations | Distinct canonical identities; no body authority inferred from spelling or declaration filename |
| JSON and .mts Program members | Membership retained even if native parser cannot represent them; no intersection-as-completeness |
| In-root link, escape, cycle and preserveSymlinks | Preserve existing link identity and refusal policy; logical project cannot widen physical boundary |
| Ambient augmentation or prototype write in dependency/sibling | Effect remains visible after domain classification; no owner proof from relabeling |
| Duplicate config keys, unresolved extends, references/plugins | Existing unsupported/ambiguous config conditions remain unavailable, never silently flattened |
| Extra, missing, duplicate or relabeled member | Reproduction/partition checks reject even when aggregate counts and names are unchanged |
| Two genuine snapshots or two genuine configs | Cross-substituting config, roots, domain rows or hash identity fails; restoring bytes starts a fresh epoch |
| Budget exhaustion, unreadable source, parse skip, empty packet | Unavailable/partial observation is explicit, not zero members or completed input proof |
