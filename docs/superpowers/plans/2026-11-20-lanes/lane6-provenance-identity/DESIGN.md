Stage D design of record, submitted for independent review. The measured base and reader labels are under
`~/prism-evidence/provenance/m/`. The full enumerated fixtures and their recorded base results are under
`~/prism-evidence/provenance/d/`. Original research is in

## 1. Intent

The provenance algorithm tells a reviewer where a changed line's values come from: user input, a database,
configuration, the environment, a constant. It is in the default review suite and in the default
`prism targets` set. Today it decides by substring on whole source lines, and most of what it reports is
wrong: on a 62-line Python file it produced 26 findings at the highest severity, including "variable
'requests' has user_input origin" for the `requests` module and the same for `subprocess`, `check` and
`run`. The lane makes each finding rest on evidence: the variable's own definition, and an origin that is
proven by what the defining expression is.

## 3. Goals, non-goals, anti-goals

Goals:

1. Findings only for variables, looked up by scope, classified from the variable's defining expression.
2. For Python, JavaScript/TypeScript and Go, each origin class is assigned by proof: a request read on a
   recognised handler parameter; a listed origin-bearing call into an import-proven database, HTTP or
   configuration library, or on a handle obtained from one; an environment read by its built-in or imported
   name; a literal; a parameter.
3. The `external_call` origin is produced (payload bytes or fields read from an HTTP client response), so the targets hint
   for it means something.
4. Other languages keep pattern classification with the structural defects fixed (variables only, scoped
   lookup, no comments or strings, gated tables, two-sided word boundaries).
5. Measured before and after on real diffs: finding volume by origin and severity; precision per origin
   class on a labelled sample of each build's findings, `info` included; and recall against a census of real
   source reads drawn from the diffs independently of both builds, each loss listed with its reason.

Non-goals: new origin classes; changing severities, the category or the description format (the targets
projection parses it); provenance across files; a cap or a ranking; removing provenance from any default.

Anti-goals: silently reporting less (every dropped class of finding is counted in the measurement); a
third copy of the import-identity proof; identity rules that only pass because fixtures were tuned to them.

## 4. Approaches considered

**A. Tighten the patterns only** (two-sided boundaries, language gating, skip comments). Removes a large
share of the noise cheaply and stays a text heuristic: `request` as a local name would still be user input.
Kept as the first slice and as the rule for languages without identity facilities; not sufficient alone.

**B. Classify the defining expression by proven identity** (chosen for Python, JavaScript/TypeScript, Go).
Uses facilities the code base already has for the same questions in taint and in targets.

**C. Derive provenance from the taint engine** (a variable is user input when a taint source reaches it).
Attractive as a single source of truth, but taint sources are seeded per diff and per framework handler,
and provenance also reports database, configuration and environment origins that taint has no notion of.
Not chosen; the request-read recogniser is shared instead.

**D. Remove provenance from the default suites until it is rebuilt.** One line, immediate relief, and a
visible behaviour change for every user. Left to the owner (section 8, decision 1); the lane does not
depend on it.

## 5. Design of record

Classify a **value read at a byte range**. A library proof identifies a contract. The contract identifies which value, if any, was read. It applies when the accessor itself is on a changed line and when a later read needs a determining definition. The reader contract is M-3 rubric v1.1.

The input ledger is `d/rows-flat.jsonl` (893 rows, SHA-256 `f7a560f1a5578072402a8211e1ea367978b91541fd44fcf37e5c58cc28553684`). `d/base-outputs.tsv` has SHA-256 `47a2ca43d60f7b8673abc1b25dcb25fc056eab5aebeb0ef948fe6be6b8d6831b`. `D-rows.tsv` decides every tentative row and every additional correction. The other rows retain their projected expectations. `D-groups.tsv` covers the same 893 input IDs. The implementer applies these ledgers to `tests/provenance_matrix/`.

### 5.1 Occurrences and definitions

#### 5.1.1 Value-read selection

Use `src/languages/mod.rs::Language` to dispatch all twelve grammars (including JSX under JavaScript). Walk runtime syntax intersecting a diff line. The existing `parsed.identifiers_on_line` and whole-line `build_import_suppression`/`classify_line` cannot distinguish two roles of one spelling. Key a read by file, line of the **root token**, half-open byte range, lexical binding and selected access path. A direct call examines its value arguments. A method call also examines a variable receiver. A calculated subscript examines its base and each evaluated index separately. Rubric v1.1 grades a receiver by what the chain selects. Thus `r` in `return count, r.FormValue("mode")` is user input, `resp` in `resp.json()` is external, and `result` in `result.rowCount` supplies only metadata. `return resp` reads the handle. `count` needs its own proof.

|---|---|
| Python | `identifier` in an evaluated operand, including the object of `attribute`, index, comprehension iterable/body, positional or keyword **value**, and real f-string `interpolation`. Exclude attribute names, named-argument labels, declaration targets, binding patterns and annotations. Resolve `global`, `nonlocal`, walrus and comprehension bindings first. |
| JavaScript, TypeScript, TSX | `identifier`, object-value `shorthand_property_identifier`, runtime `this`. | Go | `identifier` as an operand, selector operand, index, pointer/address operand, RHS list or captured formal. Exclude `blank_identifier`/`_`, package/type names, selector `field_identifier`, struct field keys, conversion type names and new declaration slots. Evaluating a destination address and writing its addressed value are separate events. |
| C, C++ | Evaluated `identifier` and C++ runtime `this`. Descend into the terminal of `qualified_identifier` when it binds data. Examine the base of `.`/`->` and both runtime operands of `.*`/`->*`. Filter before deduplicating. A simple assignment writes its target after evaluating its supplier. Augmented assignment first reads the old value. An out-argument creates a definition on the operation's write edge. Text in comments, ordinary literals, docstrings, types and malformed subtrees supplies no variable. Recover intact preceding statements, sibling functions and files (`st-py-parse-error`, `eastra-r3-lua-long-comment-unclosed-hides-apparent-code`). Visit single-character names. Drop function, class, package and direct callee spellings even when an unrelated local shares the name.

A lexical module import anchors proof. A *value* imported from a module can itself have a value-bearing chain (`from flask import request`, `from django.conf import settings`, `from flask import current_app`). JS `process`/`node:process`, Python `os` and Go package qualifiers are namespaces. Examine same-spelling locals. Ordinary instance/class formals (`self`, `cls`, Go method receivers), runtime method `this` and Lua's implicit `self` are ordinary parameters when read, including a plain projection. JS arrows capture their enclosing `this`. An erased TS `this:` consumes no runtime slot. A recognised request, service, client or handle uses its specific contract first. A locally determined field value supersedes the parameter default (`esol-r3-tsx-class-field-initializer-member-read`). A cross-method write cannot establish a handle constructor at the use.

#### 5.1.2 Reaching definitions and joins

1. Resolve the lexical binding at the read. Match a nonempty CPG Use to that occurrence, path and execution owner (`nodes_at`, `to_var_location`). Inspect its direct Def predecessors and each edge's own `FlowConfidence`. Ignore attribute ghosts, different bindings/owners and graph-only synthetic occurrences. Structural assignment pairing can recover a Java Def keyed to the complete declarator.
2. Require a feasible path after the definition's write and before the read, with no intervening must-write on that path to the selected slot. Exclude `NameOnly(Killed { .. })`. `Exact` and `NameOnly` with `SameLine`, `CfgIncomplete`, `AliasUnstable` or `CallNameOnly` are candidate edge grades. Use evaluation order within a statement and the CFG where available. A later write needs an actual back-edge reaching the read. Sharing a loop with an unconditional break or return cannot carry it. Track member/key writes separately and kill previous fields on an aggregate replacement. An unresolved alias write that could replace the selected slot invalidates its proof.
3. Use syntax for an absent/zero-width/unmatched Use, an empty predecessor set, or a projection, declarator or output definition that the graph does not represent. Recover only the missing semantic slot. A populated predecessor set exhausted by kills or impossibility cannot resurrect the earlier value through syntax. Apply the same reaching rule to syntax. Take the last effective unconditional write, union surviving branch values including a loop's zero-iteration route, and discard paths that exit, throw, break, continue elsewhere or overwrite in `finally`. Respect switch fallthrough and return/defer argument timing. Captures stay in their lexical owner. A Python class comprehension evaluates its outermost iterable in the class scope and its body in the comprehension scope. Use an invocation/creation snapshot for value captures and eager subexpressions. For late-bound captures with unknown invocation time consider only writes that can be visible on a call. Python methods skip the class namespace for free names. Use syntax at module/class/package scope. Go package initializers follow same-file dependency order, including a later textual declaration (`eastra-r1-go-package-init-dependency-on-later-variable`). Refuse cycles or dependencies outside the file.
4. Pair declarator, pattern and RHS slots before traversing them. Honour old RHS values in simultaneous assignments, JS left-to-right partial writes on exception, existing slots of Go `:=`, zero values of uninitialized specs, destructuring defaults, unpacking and `_` positions. Evaluate guards and defaults in their language scope. Loop and catch binders have their own lifetimes. An explicitly thrown value supplies its matching catch slot. Local side effects before a failing guard still reach the next arm. An assertion with optional evaluation contributes both possible paths. Java resource cleanup runs before the surrounding catch. Invalidate resource fields that an opaque close may overwrite. A resource reference and its close status are handles/control, while a read of input bytes has the reader’s data origin. A Python exception target is deleted on exit. Go `select` evaluates send operands before choosing a case. A directly invoked literal's lexical side effects can be ordered in place. An unknown call supplies no return summary.
5. Join reportable alternatives by severity (`concern` > `warning` > `info`). Within `concern`, v1.1 ranks user input above hardware. For origins at equal rubric risk break ties by earliest **reaching write to this binding**, then result operand in source byte order, then root occurrence bytes. Use the rubric risk tiers independently of the display strings from `Origin::risk_level()`. This accounts for both orders of the Viper/environment tie and the HTTP/database tie. For `||`, `??`, conditionals, block tails or match/switch arms, examine only possible *result* operands. Within one write the left result operand wins an equal-risk tie. Conditions, unselected fallbacks, discarded comma operands and unused arguments can have their own occurrences. They supply no origin to the result. Constant, opaque and control alternatives have no reportable severity. Join all occurrences of the same name on one line once for public output.

Of 577 attributed base errors, 378 involved non-variable tokens, 71 another function, 34 line inheritance, 18 signature text and 10 killed/later definitions. These counts motivate this order of selection, binding and proof.

### 5.2 Origin by proof

#### 5.2.1 Value semantics, transfers and budgets

An entry specifies a receiver, operation and result or destination slot. A handle is internal proof state carrying a type and operation history. Reading a handle by itself produces `none`. A materialized query result or selected HTTP body is data. An HTTP response envelope, database cursor, connection, session, writer, builder, metadata or status predicate carries no payload origin. Under rubric v1.1 a payload accessor gives the root occurrence its chain result and defines its paired assignment slot. Ordinary formals supply `function_param`. Literals and literal-only containers supply `constant`. A computed mixture/aggregate has no single origin as a whole. An addressable element can retain its own origin.

**`PROPAGATION_DEPTH = 3`.** A source-bearing definition is at zero. Charge one transfer when a new data binding copies a previous binding by alias, projection, destructuring/iteration, or a listed conversion. Pair projections to their supplier within one expression. Parentheses, `await`, erased casts, address/dereference and structural result selection do not add binding transfers. A listed pass-through consumes one transfer from its selected input to its output, including when nested. Count a pass-through supplying a binding once. Reading the final binding costs nothing. Stop before a fourth transfer, on a cycle or an unproven input. `py-prop-1`, `xfer-py-depth-kept`, `py-prop-limit` require one, two and three plain copies. The third is a real source under v1.1. Pair it with the same fixture extended by `fourth = third` as the over-limit negative.

**`HANDLE_HOP_DEPTH = 3`.** Count the constructor as step one and each listed handle-producing transition as one more, including a fluent operation returning its receiver. An imported concrete formal starts as a typed root at zero. A terminal payload read/output costs no handle hop. `await`, `with ... as` and ordinary aliases do not manufacture handles. Bound alias traversal separately by the data budget. Each hop needs **one reaching definition of the receiver at the use**, or a concrete type specified below. Two live branch constructors fail uniqueness. Two sequential assignments with the first killed have one reaching constructor. `py-db-sqlite-hop2` needs two, `hops-py-sqlite-limit` and `esol-r1-go-sql-tx-queryrow-scan` need three. In `eastra-r1-py-sqlalchemy-mapping-result-vs-result-column-keys`, engine → connection → execution result → mappings view is four before the terminal read. Trace `handle-depth`. The census did not measure either depth distribution.

The pass-through list is closed. A call may select an existing argument, payload field or output argument only where its family table says so. In particular Python `typing.cast` selects argument 1, JS `JSON.parse` selects input 0 under its parser conditions, and Go `strconv.Atoi` selects input 0 for result 0. There is no general transfer for Python `str/int`, JS `String/Number`, arbitrary methods named `get`, or a call merely receiving the data. Alongside structural result selection and plain projections, use only the parsing, reading and conversion slots in §§5.2.2–5 and the explicit pattern-language transfers in §5.3. Arithmetic, formatting, concatenating local and outside text, comparisons and ordinary user calls supply no source to their result. A local adapter, hook, setter, overwrite or known exhaustion invalidates only its affected slot. Admit statically paired projections from local bindings, field assignments, destructuring and documented callbacks. General heap and interprocedural reconstruction are outside the model.

In the tables braces enumerate exact members. Missing names/overloads give `unlisted-call`. On a supported read, honor the known success, failure, nil/EOF or default branch before selecting a slot. Canonical qualifiers and aliases require §5.4. A generic parser preserves its **actual input origin**. A configuration input for generic parsers is a read-only literal path (or one relative to a known module directory) ending in `.ini`, `.conf`, `.properties`, or with basename `config`, `settings` or `configuration` and extension `.json`, `.yaml`, `.yml` or `.toml`. A configuration facility's explicit file-load operation also establishes purpose, including for an application-chosen path. Parsing request, network or environment bytes preserves that origin. Literals, unclassified paths, status results and replacing hooks do not acquire `config` from a parser name.

### 5.3 Code-only patterns for the other languages

S1 applies the role, binding, slot, join and trace rules to **every** grammar. Match token sequences on a determining expression or designated output operation. Respect the grammar's identifier boundaries on both sides (including Java/JS `$` and Rust raw identifiers), qualification, lexical shadows and actual call delimiters across whitespace/comments. Inspect every candidate, including a valid one following a prefix decoy. Match exact callees, receivers and outputs. Mask literal content except explicit runtime substitutions. Literal arguments may select a contract slot (e.g. scanf format, ioctl request or config path). They are never searched for source substrings. A trigger on a defined name, argument, unused child, neighbouring statement or diff line supplies no origin. This resolves `getenv(argv[1])` by the callee's return contract. There is no universal `request`, `input`, `args`, `form`, `query`, `fetch`, `SELECT`, `settings`, `config`, `env`, `read` or `find` table.

The dispatch is exhaustive. C and C++ share the C entries. C++ adds its stream rules. Java, Rust, Lua, Bash and HCL each use only their section below. Foreign C spellings are admitted only through the explicit Rust/Lua FFI forms. Python, JS/JSX/TS/TSX and Go temporarily use their own existing code-shaped families in S1 (e.g. `input`, `sys.argv`, `process.env`, `request.GET`, `r.FormValue`, `r.URL.Query`, `os.Getenv`, `cursor.fetchone`), with the shared role, slot and transfer corrections. Retain direct positive controls including configuration reads and registered handler shapes while moving to the final proof tables in S3–S5. A family identity row may turn green incidentally before its proof arrives. No identity family has a pattern fallback after its migration.
