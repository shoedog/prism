Brackets indicate optional arguments, `...` permits repetition, and vertical bars separate alternatives. Each kit `--out` directory must be absent or empty on entry. Section 7 defines benchmark acquisition and reuse. Obtain exclusive ownership before starting, preserve existing files on refusal, stage outputs and publish the completion record last. ## 2. Corpora, binding and run receipts

`corpora.json` is `{"schema":"prism.measure.corpora/1","corpora":{KEY:entry}}`. Each entry declares `name` (display string), `kind` (`git` or `tree`), `url` (public upstream or null), `commit` (full 40-hex Git commit or null), `root` (query subdirectory, `.` allowed), `history` (boolean), `local` (ordered array of relative paths to the checkout or extracted tree), `manifest_sha256` (perf-cloud regular-file manifest digest or null), `cloud_asset` (release asset basename or null), `tree_sha256` (registered §2 input digest, nullable for Git-only lookup), and optionally `archive_sha256` for transport. A git checkout requires its commit. For `kind="tree"` the manifest pins the complete query root by `tree_sha256` at registration, including symlink paths, types and raw target text. A tree entry uses manifest verification even if its fixture lives inside the kit checkout. Asset names and abbreviated commits confer no pin. **Input digest.** Walk the query root without following symlinks. Omit every path component exactly `.git`. Include every regular file and every link, including directory and dangling links. Sort by unsigned pathname bytes (relative POSIX spelling, `os.fsencode`). Feed SHA-256 the concatenated records `type || u64be(len(path)) || path || u64be(len(value)) || value`. Type is the single ASCII byte `F` or `L`. Value is raw file bytes or the link target's raw text. Empty directories, timestamps and permissions supply no bytes. Reject unreadable members and special files. `verify` and `run` additionally check every link. A dangling link is admitted with its raw link text bound by the digest, since no bytes outside the digest can be read through it. A link that resolves through relative, in-root components to a regular file included in the digest, or to a directory inside the root outside `.git` (whose files are already walked into the digest), is admitted. Refuse `unbound-link` (3) on any hop that is absolute, leaves the root or enters `.git`, and on any cycle.

**Execution.** Check arguments/output and hash the prediction’s raw bytes. Before `--version`, prepare a private snapshot outside the source (a verified copy of the query tree without Git metadata, for Git and extraction inputs alike). Verify its digest and link closure against the same pin. Use it as `ROOT` for every analysis and retain it for receipt-bound reads. Hash the executable before version, before each analysis and after the last command. A byte change fails the run. Hash the guard and its host-quiet helper (`../hostquiet/host_quiet.py` relative to the guard file; null when absent or not a regular file; other dependencies of a custom guard are not bound, open-n3-21) at the same points; a change fails the run (4, or 75 when a later attempt reports host quiet after an analysis has launched); once an analysis has launched the failed receipt is retained, before that there is none. The guard must be a readable executable regular file. An artifact a later command rewrites or deletes is recorded in `artifact_drift` (captured and retained digests) on the failed receipt, which publishes the surviving files. The guard runs version and each command serially with default limit 8 GiB (positive integer override). Accept `--expect-version` only when it equals the version token or a prefix of the reported commit token, case-insensitive for hex. A version mismatch starts no analysis. Pre-analysis host-quiet (including the first analysis being refused before launch) yields 75 and no receipt. After any analysis has launched, stop at the first nonzero, keep completed/partial outputs and write a failed receipt, including on a late 75. After the last attempted analysis recheck the snapshot and original root against the admitted digest. A changed digest gives status `input_changed` and exit 4 except that a late guard refusal retains exit 75. Unreadable final input, executable drift or other failure gives `failed`. A standalone run retains the prediction digest captured at entry if the prediction changes.

Each argv starts `BIN nav --no-cache` followed in order by `dfg-stats --repo ROOT`, `call-stats --repo ROOT`, `dfg-stats --repo ROOT --edges` and, with `--sites`, `call-stats --repo ROOT --dump-sites`. Start with a clean product environment: remove inherited `PRISM_*` and guard-bypass settings. Set `PRISM_EDGES_BYTES=1` only for the edge dump unless `--no-bytes`, then leave it absent. Only that command receives explicit trace overrides. Accept distinct `PRISM_[A-Z0-9_]+` names with a value (split on first `=`), except the reserved byte switch. Pass only the host runtime variables `PATH, HOME, TMPDIR, TEMP, TMP, SYSTEMROOT` when present and fix `LC_ALL=C`. Record the effective fixed and product settings. Resolve the guard from `--memguard` or `scripts/memguard/memguard.sh`. Its quiet helper is repository-relative, its log uses `MEMGUARD_LOG` or the XDG state default. Never copy the host's kill log. A structured quiet refusal returns control to the caller for waiting. This CLI takes no quiet marker.

**Guard status.** The kit supplies a fresh status pipe on a dedicated inherited descriptor (`--status-fd FD` before the limit). The guard closes the descriptor in the product child and writes one JSON object and LF on completion, before exiting. A caller that cannot start the guard records an execution error locally. `{kind,launched,child_exit}` is `host_quiet,false,null` on a live marker, `child,true,N` on child completion, or `rss_unavailable`, `rss_limit` or `guard_error` with the actual launch flag and reaped child status if launched. Encode signal termination as 128 plus the signal number. Keep the raw wrapper exit and status on each guarded attempt. Check consistency with §1. Missing, duplicate, malformed or inconsistent status is a guard execution error. Only `kind="host_quiet"` can interrupt a gate for host quiet. A launched child returning 75 follows the ordinary failure path, including retention of a partial run receipt if analysis started. Without the optional descriptor the guard preserves its standalone shell contract. A worker the command leaves running in its process group after it exits is terminated and reported as `guard_error` with `launched=true` (exit 1), with or without the descriptor, so a standalone command that deliberately leaves a background worker exits 1 and its group is terminated.

## 3. Edge difference, trace join and counters

The edge wire object has `from,to,confidence,doubt` and optional `kill_line`. Each endpoint has `file,line,path:{base,fields},access` and optional `start_byte,end_byte`. File and path base are strings, fields an **ordered** string array (including literal `[]`). Access is `def` or `use`. Lines are positive integers. Supplied byte offsets are nonnegative integers or null, half-open, start ≤ end when both present. Zero-width anchors and byte zero are valid. Confidence is `exact` or `nameonly`, doubt null or a nonempty doubt string, kill line null/absent or a positive integer. Exact requires null doubt. A synthetic nameonly/null is compared literally. Additional object members, including owner, survive in the raw dump but do not enter identity or attributes. Unknown shapes of required fields refuse the stream.

**Key and cancellation.** `K={from:E,to:E}` with `E={file,base,fields,line,start_byte,end_byte}`. Automatic mode checks every endpoint across both complete streams. All carry both bounds → `bytes`. All carry neither → `line`. Anything mixed or partial → exit 2. An empty arm adds no constraint. For two empty streams choose the shared receipt option (`bytes` unless `--no-bytes`). Explicit `bytes` requires both bounds on every observed endpoint, including both ends of a zero-width span. Explicit `line` replaces both bounds with null on every endpoint and applies to both runs and edge-record match keys. If explicit line mode discards any supplied byte bound on either arm, require a nonblank `--line-reason` (gate `line_reason`) or refuse admission. A historical line-control prediction is a valid reason. Check after scanning both complete streams. Set `line_projection_loss` to this condition and retain `line_reason` or null even at zero changes. Stage-T explicit-line fixtures supply “matrix line projection” unless testing the missing reason. A collision is a distinct projected key with multiplicity >1 on **either** arm before cancellation, including unchanged keys. Report zero collisions in byte mode.

For each ordered endpoint pair form two multisets of `A={from_access,to_access,confidence,doubt,kill_line}`, normalizing absent kill line to null. Cancel `min(B[A],H[A])` for every **whole** attribute tuple. With residual lengths `b,h`:

| Residual | Emitted change rows for K |
|---|---|
| Both zero | None. Keep the cancelled occurrences in the unchanged index. |
| One empty | One `added` or `removed` row containing the entire nonempty bag, including distinct attributes. |
| Both nonempty, larger side homogeneous (either side homogeneous on a tie) | Pair every smaller-side occurrence with the single available larger-side label. Emit one `label_moved` row per distinct ordered transition, `count` equal to its multiplicity. Put any surplus in one one-sided row. |
| Otherwise | One `ambiguous` row with both complete residual bags. Only a class returned for this entire row attributes it. |
