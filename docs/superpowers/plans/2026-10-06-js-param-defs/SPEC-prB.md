### Recorded by the R10 hunk check (Opus, 2026-10-10; `reviews/prB-r10-check-opus.md`; verdict APPROVE)

All four are WRONG / IMMATERIAL with fixture reproducers and no incidence on X, Xi, T or the 576 admitted SecBench roots (the R10 head-to-head difference set is empty). The controller recorded them and did not open another source round. Under a strict reading of "zero false edges / no LOST correct rows" each is a contract instance; they are disclosed here for that reason.

- **R10-1 (created by the R10 enum hunk).** `function q(y: number){ enum yield { y = 1 } enum await { z = y } use(y); }` loses main's NameOnly row from the formal to the read on the last line. Two enum names that both fail identifier decoding compare equal (`None == None`), so the two enums are treated as one merged enum. Fix: compare raw text when neither name contains a backslash. Applies only to enums named `yield` or `await`.
- **R10-2 (unchanged from `96817370`; the named-owner row is also on main).** One enum declared in two `case` clauses of a `switch` is not treated as merged, so the initializer read is emitted as an Exact row from the formal although TypeScript binds it to the member. Fix: scan all clauses of the enclosing `switch_body`.
- **R10-3 (unchanged from `96817370` and main).** Computed literal enum keys (`["y"]`, a template literal key) are not fenced. Fix: peel `computed_property_name` around a literal.
