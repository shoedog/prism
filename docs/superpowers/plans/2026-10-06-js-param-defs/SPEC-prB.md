**Status:** planner prototype for the first spec-review round (cap 2). Uncommitted working tree on `plan/js-param-defs-prB`. **STOP-1 open (owner decision, §8): the mandated E3 fence changes DataFlow-derived nav output (`ego`, `nodes-at`), which the brief requires to stay byte-identical.**

## Goal (decision served)
JS/TS/TSX anonymous callables (call arguments, assignment RHS, nested statements, JSX `onClick={e=>…}`, `.map(x=>…)`, `useEffect`, IIFE, `return`) get their **own DFG pass** under a **synthetic, non-referenceable identity**, so their formals get Defs. This is the identity half of the SecBench `callback_argument_parameter_registration` population (97 entries); PR-C supplies the member half.

Requirements (owner brief): zero false Defs or edges; 0 LOST correct rows; no RE-OWNED wrong rows; nav output byte-identical by default; call sites unchanged; non-JS byte-identical. Exact stays a static-binding grade; every ambiguity resolves toward no edge.

**What PR-B alone delivers (read this before reviewing):** on the unmodified packages it converts **0/97** SecBench rows to `traced`. 95/97 payload formals are member-only (PR-C) and the other 2 need an outgoing call from a top-level callback, which has no call site (non-goal). With one bare read inserted per payload (the R1 `member` checkpoint, callback kept anonymous), PR-B's head traces **90/97** (payload-specific BFS 90/90; base 1/97). The harness still reports `prism_error` for all 96 because `callees --location` at an anonymous callable is `LocationOutOfRange` while nav stays byte-identical (owner decision O1, §8).

## §0 Decisions
| # | Decision | Why (evidence) |
|---|---|---|
| B-D1 | **Synthetic identity is a DFG-owner name only.** `ParsedFile::dfg_owner_name` = `function_name` when it exists (name inference always wins), else `<cb@LINE:COL>` (1-based line, 1-based byte column of the callable's first byte) for an unnamed JS/TS/TSX `arrow_function`/`function_expression`, else `None`. Only `data_flow.rs` (and the probe byte dumper) call it. `FunctionInfo.name`, `Language::function_name`, the call graph, the owner index, `free_single`, `functions_named`, symbol seeds and nav symbols are untouched, so the name cannot enter resolution by construction. | `<` cannot start an identifier; every name `function_name` returns for JS/TS is an identifier, a property name, a quoted string key or a bracketed computed key (pinned by `synthetic_spelling_is_unspellable_by_any_real_owner`). Two callables never share a first byte. |
| B-D2 | **Own-scope ownership, legacy coverage unchanged.** A synthetic pass owns only bytes inside its callable and outside nested callables (lvalues, aliases, rvalues; references may cross into nested callables as captures, behind the E3 fence). Named passes keep their line-based coverage **byte-identically**, so a callback nested in a named function keeps its legacy rows and gains parallel synthetic-owned rows, exactly as a *named* nested callable does today (E9, parity). | **Rejected: re-owning** (fence legacy passes out of callbacks). `trace.rs::taint_neighbors` propagates Use→same-line Def only within one owner, so re-owning breaks `function h(cmd){ xs.forEach(i => { const c = cmd + i; exec(c) }) }` (capture read owned by `h`, Def `c` re-owned) — a lost taint path — and turns every nested row into RE-OWNED (+ NameOnly→Exact relabels). Own-scope also fixes E1 for new passes: `const r = f(xs.map(x => …))` never puts `r` in the arrow's pass. Measured RE-OWNED: **0** on every corpus. |
| B-D3 | **E3 binder fence on every JS/TS reference walk** (legacy and new; `find_path_references_fenced_in`). A reference is fenced when an ancestor scope strictly between it and the owner binds the same name and does not contain the Def's bytes: nested callable formals and function-scope (`var` incl. `for (var k in …)` heads, body-level declarations), function/class-expression self names, catch parameters, `let`/`const` for / for-in / for-of heads, block-level `let`/`const`/function/class declarations. Synthetic passes additionally stop `this.x` paths at nested non-arrow functions/methods/class bodies (another receiver). Escaped binding spellings fence (fail closed). `var` heads and captures are not fenced. Non-JS walks delegate unchanged. | Brief must-address 2; E3 (SPEC-prA §6). Measured LOST rows are **all checker-WRONG** (X 2,689, Xi/T/SB in MEASUREMENTS). Both directions tested (`enclosing_walk_never_reaches_nested_binders`, `enclosing_walk_keeps_captured_reads_and_var_redeclarations`). |
| B-D4 | **Captured reads are never re-emitted.** A callback pass has no Def for a binding declared outside it, so it emits no row for a captured read; the enclosing legacy row keeps its bytes and the B8 PROVISIONAL `NameOnly(CfgIncomplete)` label. | `captured_read_rows_are_byte_identical_to_the_legacy_owner`. |
| B-D5 | **E5 isolation.** Synthetic owners are never callees (no `FunctionId`), never resolved callers, so no Step-5b argument or return-flow edge enters or leaves a synthetic owner. Calls inside a top-level callback still have no call site; calls inside a nested callback keep their legacy caller and gain no edge. Call-site output is byte-identical. | `anonymous_callables_are_never_interprocedural_endpoints`; call-site dumps identical on every corpus. PR-A's D12 outgoing refusal therefore never sees a synthetic source (no cross-owner DataFlow edge exists). |
| B-D6 | **D11 (PR-A competing-binder refusal) is kept**, not retired. | Retiring it buys nothing measured (R1: D11 cost 0 rows) and would need the full escaped-binder proof. |
| B-D7 | **Synthetic identities are invisible to nav.** No `Function` node is created for a synthetic owner; `nodes-at` and `ego --location` filter synthetic-owned `Variable` nodes (`nav_visible_nodes_at`). `symbol-spans`, `callers`, `callees`, `module-deps`, `repo-map`, call-site dumps unchanged; `NAV_CALL_EDGE_CACHE_VERSION` unchanged. `dfg-stats` and `taint-reaches` change by design; reasoning location seeds see synthetic Defs. **Not achieved: full nav byte identity** — B-D3's fence removes legacy Variable anchors and DataFlow edges that `ego` (default edges include DataFlow/Contains) and `nodes-at` list (STOP-1). | Tested (`navigation_hides_synthetic_variables_but_taint_seeds_see_them`, `synthetic_identity_never_resolves_as_a_symbol`). Nav probe (b6): X 1/241 and T 2/81 sampled queries differ, all `ego`; the X one is entirely removed anchors of LOST checker-WRONG rows (T's two not inspected); no `<cb@` in any output; 0 sampled `nodes-at` diffs. |
| B-D8 | `CACHE_VERSION` 107 → 108 (one transition). PD-11 and lane-P P2-M11 are re-pinned together. | DFG rows change. Opus F6 coupling. |
| B-D9 | **E7 must not grow:** a synthetic pass drops rvalue spans whose exact node is a non-reference token (`property_identifier`, `private_property_identifier`, `statement_identifier`, `type_identifier`: pair keys, JSX attribute names, member/callee property names). Legacy passes keep base parity. | Brief must-address 5. b1 prototype measured 33 E7 WRONG ADDED rows on X before this filter; 0 after. It is the token-kind half of PR-C's classifier and can be shared; PR-C still needs the base-binding half. |
| B-D10 | **E10 must not grow:** a synthetic pass's `let`/`const` Def (declarator or `for (const k of …)` head) reaches only references inside its block / loop. | b1: Defs reached same-name references in sibling blocks and before the loop (checker-WRONG). Legacy keeps parity (E10, disclosed). |
| B-D11 | **E11 must not grow:** a synthetic pass derives its aliases only from its own-scope lvalue identifiers (`js_ts_own_alias_target`: plain `a = b`, `var a = b`, flat `const {k} = o` / `{k: a} = o`; never `x += y`, array or nested patterns), and creates a twin only on the line that establishes the alias, to that line's target (`resolve_on_alias_line`). | b1: the flow-insensitive alias map retro-applied later aliases and turned alias re-assignment into a "write" of the target (45 checker-WRONG on X). ## Non-goals (disclosed)
- Anonymous `function*` expressions (`generator_function` is not in `function_node_types()`; adding it changes the function table).
- The legacy `arguments` object.
- Callback **invocation** edges (a registration is not an invocation; consumer-visibility doctrine).
- Outgoing interprocedural flow from a callback body: no Step-5b edge from a synthetic owner, and no call sites for code outside named functions (would change call-site output). 2/97 SecBench rows need it.
- Member-only formals (PR-C). Destructured parameters.
- Fixing E4/E7/E10/E11 in legacy named passes (base parity, disclosed).
- Nav visibility of anonymous callables; SecBench harness changes (owner O1).

## §6 Pre-existing defects surfaced (recorded, not fixed in legacy passes)
- **E9 (SMELL, parity):** a callable nested in a named function is owned twice — by its own pass and by the enclosing named pass's line coverage. True for named nested callables on base; PR-B extends it to anonymous ones. Wire rows can repeat with different owners (counted in MEASUREMENTS). Seeds on such lines see two owners and take the existing pure-taint fallback (`trace.rs` "multiple functions").
- **E10 (WRONG, legacy parity):** a legacy `let`/`const`/for-head Def reaches same-name references outside its block (the walk never checks that the Use lies in the Def's scope). Fixed for synthetic passes only (B-D10).
- **E11 (WRONG, legacy parity):** legacy alias twins are flow-insensitive (`alias_map` is per function): a later `b = a` makes an earlier `b = f()` a "Def of `a`", and the twin reaches the formal's own declaration. 200 of X's LOST rows were E11 rows the E3 fence removed. Fixed for synthetic passes only (B-D11).
- **E4/E7 (inherited):** legacy parity unchanged; not grown by PR-B (B-D9, B-D12).
- **E3:** fixed (B-D3).
- **E1:** fixed for synthetic passes (own scope); legacy named arrows unchanged.

**Known residue (WRONG, synthetic rows, closed and enumerable):** 12 SecBench ADDED rows (of 255,886) on minified lines where two declarators of one name share a line: the synthetic alias twin is keyed by `(name, line)` (`resolve_on_alias_line`) and attaches to the declarator that is not the alias. Bounded fix: key the twin by the lvalue span's start byte. Not applied in this prototype (STOP-1 pending); X and T have 0 ADDED WRONG.

## §8 Owner decisions

### STOP-1 — nav byte identity vs the E3 fence (brief: "STOP and report, do not choose" on a nav change)
The brief requires both (must-address 2) that the enclosing pass create no edges into a callback's formals or D11 binders, and that nav output stay byte-identical. These conflict: `nav ego` (default `--edges Call,Return,DataFlow,Contains`) and `nav nodes-at` list a named function's `Variable` nodes, including zero-width Use anchors that exist only as endpoints of E3 rows. Removing the checker-WRONG rows removes those anchors and edges. Measured (b6 head, `nav_identity.py`): X 1/241 queries differ (`ego` at `ConvertElementTypePopup.tsx:499`: 260 → 253 nodes, 292 → 285 edges; every missing node is a zero-width Use anchor of a LOST WRONG row), T 2/81 (`ego`, not inspected). No sampled `nodes-at` query differed, but `nodes-at` lists the same anchors, so it changes on any line that held one. `callers`, `callees`, `repo-map` and every call-site dump are identical; the same mechanism lowers `call-stats.return_flow.return_input_edges` (X 3,863 → 3,789, PB11). Options (planner does not choose):
- **(a) Accept** the nav delta as the E3 fix's direct consequence; restate the nav contract as "symbol, call and module nav byte-identical; DataFlow-derived nav (`ego` DataFlow/Contains, `nodes-at` Variables, ReturnInput) changes exactly where checker-WRONG E3 rows are removed". Cost: nav-cache consumers see different ego graphs on affected lines (no new nodes, only removals). No code change.
- **(b) Fence synthetic passes only.** Legacy rows, nav and `return_input_edges` become byte-identical; E3 stays a disclosed legacy defect (T keeps 368,854 false rows, SecBench 588,862); must-address 2 is then unmet for named enclosing passes. Code change: gate `js_ts_reference_fenced` on `reads_only`; re-measure.
- **(c) Fence edges but keep the anchors** (register fenced references as edge-less Use nodes). `nodes-at` stays identical; `ego` still loses the DataFlow edges, so (c) does not restore identity by itself. Not recommended without (a).

- **O1 (harness credit):** `measure()` needs `callees --location <source>` to succeed; at an anonymous callable it is `LocationOutOfRange` on base and head. Options: (a) eval-only harness change — treat that error as empty callees when the source line opens an anonymous callable (no product change; the callee-tolerant numbers in MEASUREMENTS are exactly this); (b) make synthetic callables navigable (nav + Tier-A frame change, `NAV_CALL_EDGE_CACHE_VERSION` bump, resolution-isolation re-proof); (c) accept no harness credit until a later lane.
- **O2 (sequencing):** ship PR-B now (identity + E3 fix + perf memo; 0 standalone conversions) or hold it to land with PR-C (joint 90/97 projected).
- **O3:** outgoing interprocedural flow from callbacks needs call sites for code outside named functions (call-site change); separate lane if wanted.
