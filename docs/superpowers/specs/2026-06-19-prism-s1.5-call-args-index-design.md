# Prism S1.5 — Per-File Call-Args Index (Design)

**Rev 2 — 2026-06-19. Status: PLAN-READY (codex gpt-5.5 xhigh spec-review folded).**

> **Rev 2 (codex spec-review — SOUND-WITH-CONCERNS → PLAN-READY, no blockers):** folded 1 MAJOR + 4 MINORs.
> §3.2 nav-laziness benefit restated — the cold/no-cache nav index build *does* run Step 5b (and benefits
> from the index); lazy saves warm-cache-hit / AST-only / no-arg paths, not "all nav." Consumer census
> narrowed to the byte-keyed plural API; the singular `call_argument_text_at` + the line variant are marked
> explicitly out of scope (§2). §3.4 text derivation made panic-safe (mirrors `node_text`'s
> `utf8_text().unwrap_or("")`). §4 parity corpus extended to all 12 `Language::all()` variants. Perf/alloc
> wording corrected — extraction is per-resolved-callee; the span read allocates 1 String/arg (vs legacy's 2)
> + 1 key String/lookup.

**Goal:** Remove the per-lookup full-tree walk in `ParsedFile::collect_call_args_at`
by building a per-file call-argument index once. Pure perf refactor —
**behavior-preserving, byte-for-byte identical output.**

**One-liner:** `assemble_graph` Step 5b calls `call_argument_texts_at` once per
call site, and each call re-walks the file's whole tree from the root → O(call-sites
× tree) per file. Index the file's call nodes in one pre-order walk so each lookup
is a `BTreeMap` hit.

## §1. Context & diagnosis

S1 (`2026-06-11-prism-s1-perf-level4-index-design.md`) eliminated the
`all_functions` re-walk via the eager FunctionTable. Its follow-up notes
(`docs/archive/plans/prism-query-layer/s1-followups.md`) record the next dominant hotspot:

- **Item 3:** "`collect_call_args` recursion is the next dominant hotspot. With
  `all_functions` eliminated, ~98% of remaining `assemble_graph` time at tokio
  scale is the deeply recursive `ParsedFile::collect_call_args` walk under Step 5b.
  Step 5b is deliberately serial assembly territory, so C2 does not mask it.
  Candidate S1.5: per-file call-args index (same shape as the FunctionTable move)."
- **Item 9:** the cold wall-clock gate (spec §7 row C) is **NOT MET** — cold-hugo
  user/wall ≈ 1.05 vs the ≥1.5 target — *because* "the cold path is dominated by
  the serial Step-5b `collect_call_args` walk (item 3)." The row is open evidence,
  to be re-measured "after the item-3 follow-up removes the serial dominator."

S1.5 is that follow-up.

### The hot path

`src/cpg/build.rs:428` (Step 5b — interprocedural data-flow edges):

```rust
for (caller_id, sites) in &cg.calls {        // every caller
    for site in sites {                       // every call site
        for resolved in cg.resolve_call_site(site) {
            ...
            let arg_texts =
                caller_parsed.call_argument_texts_at(site.start_byte, &site.callee_name);
            ...
```

`call_argument_texts_at` → `collect_call_args_at` (`src/ast.rs:4356`) walks from
`self.tree.root_node()` until it finds the call node whose `start_byte` matches.
For a file with N call sites that is N independent O(tree) descents.

### The arg-text consumers (whole codebase)

| consumer | method | keyed by | path | S1.5 |
|---|---|---|---|---|
| `cpg/build.rs:438` Step 5b | `call_argument_texts_at(start_byte, name)` | **byte** | whole-repo assembly — **the 98% hotspot** | **indexed** |
| `absence_slice.rs:490` `close_matches_resource` | `call_argument_texts(line, name)` | line | per-diff, per detected close-call — cold | walk (out of scope) |
| `call_graph.rs:901` callback Level-3 resolution | `call_argument_text_at(line, name, arg_index)` (singular, ast.rs:4253) | line | per callback site, narrower than Step 5b | walk (out of scope) |

Step 5b iterates resolved `CallSite`s, which carry `start_byte`, so it uses the
precise **byte-keyed plural** form — the only API S1.5 indexes, and the entire 98%
(via `collect_call_args_at`). The other two are **line-keyed** and stay as walks (§2):
`absence_slice` detects close-calls by scanning lines (open/close resource pairs) and
has only `(line, name)`; the singular `call_argument_text_at` (a separate walker,
`find_call_arg_at`) returns one arg by index for callback resolution. Both run on
narrower/cold paths, and a byte-keyed index does not serve a line query anyway.

## §2. Scope

**In scope:** index the **byte path** (`call_argument_texts_at`) — the entire 98%.

**Out of scope (explicit non-goals):**
- The **line-keyed paths** stay as today's recursive walks: `call_argument_texts` /
  `collect_call_args` (absence_slice) **and** the singular `call_argument_text_at` /
  `find_call_arg_at` (callback Level-3 resolution, `call_graph.rs:901`). Both are
  cold/narrow, and a byte-keyed index does not serve a line query — a line index for
  these is a deferred follow-up, not worth the surface for S1.5.
- **No behavior change.** Output of `call_argument_texts_at` is byte-identical
  before/after. No new resolution, no arity changes, no DFG-edge changes.
- **No type-inference or tracing consumers built here.** The value type is chosen to
  *not foreclose* them (§5), but none are implemented in S1.5.
- The adjacent `all_functions()`-per-site reconstruction in the same Step-5b loop
  (s1-followups item 6) is already FunctionTable-backed and is not touched.

## §3. Design

### §3.1 Data types (span-based, reuse-ready)

```rust
/// One argument of a call, as a source byte-span (the S2 byte-identity anchor).
/// Argument *text* is derived on demand so the index can later carry typed-arg
/// info / re-descend to the node without a rewrite (§5). Read-side alloc is
/// favorable: the span read does ONE `String`/arg (vs the legacy walk's two —
/// `.trim().to_string()` then `.trim_start_matches('&').to_string()`) plus one
/// key `String`/lookup; and the one-time index build replaces N tree-walks with one.
#[derive(Clone, Debug, PartialEq, Eq)]
pub(crate) struct CallArg {
    pub start_byte: usize,
    pub end_byte: usize,
}

/// Per-file index of call arguments. Built once per file by a single pre-order
/// walk; replaces the per-lookup full-tree walk in `collect_call_args_at`.
/// Keyed by `(call_node.start_byte, callee_name)` — see §3.3 for why the name is
/// part of the key.
#[derive(Clone, Debug, Default)]
pub(crate) struct CallArgsIndex {
    by_call: std::collections::BTreeMap<(usize, String), Vec<CallArg>>,
}
```

`CallArg` stores spans, not pre-extracted text. Text is derived at read time
(§3.4) to byte-match the legacy walk exactly. Rationale for spans over text in §5.

### §3.2 Placement & laziness

Add a lazily-built field to `ParsedFile` (`src/ast.rs:82`), mirroring the existing
`framework: OnceLock<…>` house style:

```rust
pub struct ParsedFile {
    ...
    functions: Vec<FunctionInfo>,
    /// Lazily-built call-argument index, populated on first call to
    /// `call_argument_texts_at`. Lazy (not eager like `functions`) so warm
    /// nav-cache loads, AST-only consumers, and callers with no resolved-call args
    /// pay nothing; the cold CPG/nav build that runs Step 5b builds it on demand.
    call_args: std::sync::OnceLock<CallArgsIndex>,
}

impl ParsedFile {
    pub(crate) fn call_args_index(&self) -> &CallArgsIndex {
        self.call_args.get_or_init(|| self.build_call_args_index())
    }
}
```

**Lazy, not eager** — unlike the FunctionTable, which nav reads via
`all_functions`/inventory. The byte-keyed index's only reader is Step 5b. Nav query
*handlers* (`callers`/`callees`/`ego`/`module-deps`/`repo-map`) never call it — but
the **cold/no-cache nav index *build* does** run Step 5b (`navigation/cache.rs:65,89`
→ `CpgContext::build_with_scope_graph_inputs` → `assemble_graph`), so S1.5 speeds the
nav cold-build too. A **warm** nav-cache hit reconstructs from the serialized CPG
(`build_with_cached_cpg`, `cache.rs:53`) and does **not** run Step 5b. So lazy avoids
the index cost exactly where it's wasted — warm-cache loads, AST-only consumers, and
callers with no resolved-call args — while the cold build that needs it pays once.
Eager building (in `ParsedFile::new`) would instead build it on every parse, including
those wasted cases. `OnceLock` is `Send + Sync` and safe under the rayon-parallel
build (and the current Step 5b serial walk); concurrent first-callers race once, then
share.

`OnceLock<CallArgsIndex>` is `Clone` when `CallArgsIndex: Clone` (a clone before
first use is empty; after, it carries the index) — consistent with the existing
`framework` OnceLock under `#[derive(Clone)]`. The field is added to the `Self { … }`
literal in `ParsedFile::new` as `call_args: OnceLock::new()`.

### §3.3 Build (single pre-order walk)

```rust
fn build_call_args_index(&self) -> CallArgsIndex {
    let mut by_call = BTreeMap::new();
    self.index_call_args(self.tree.root_node(), &mut by_call);
    CallArgsIndex { by_call }
}

fn index_call_args(&self, node: Node<'_>, out: &mut BTreeMap<(usize, String), Vec<CallArg>>) {
    if self.language.is_call_node(node.kind()) {
        if let Some(name_node) = self.language.call_function_name(&node) {
            let name = self.node_text(&name_node).to_string();
            let key = (node.start_byte(), name);
            // First pre-order occurrence wins — exactly mirrors the legacy walk,
            // which returns the first matching call node in pre-order DFS.
            out.entry(key).or_insert_with(|| self.named_arg_spans(&node));
        }
    }
    let mut cursor = node.walk();
    for child in node.children(&mut cursor) {
        self.index_call_args(child, out);
    }
}

/// The named argument spans of a call node (the build/lookup-shared extractor).
fn named_arg_spans(&self, call_node: &Node<'_>) -> Vec<CallArg> {
    let mut args = Vec::new();
    if let Some(args_node) = self.language.call_arguments(call_node) {
        let mut cursor = args_node.walk();
        for child in args_node.children(&mut cursor) {
            if child.is_named() {
                args.push(CallArg { start_byte: child.start_byte(), end_byte: child.end_byte() });
            }
        }
    }
    args
}
```

**Why the name is part of the key.** Two call nodes can share a `start_byte`: in
`a.b().c()` the outer `call_expression` (`a.b().c()`, callee `c`) and the inner
`a.b()` (callee `b`) both start at byte(`a`). The legacy `collect_call_args_at`
matches on `start_byte` **and** `callee_name`, returning the first pre-order match —
so `(start_byte, name)` is the faithful key. First-write-wins in pre-order
reproduces the legacy first-match.

**Pre-existing latent ambiguity, preserved (not fixed).** If two call nodes share
*both* `start_byte` and name — `a.b().b()` (outer + inner both callee `b`, both
start at byte(`a`)) — the legacy returns the **outer** (first pre-order). The index
does the same (first-write-wins). This is a faithful preservation of existing
behavior; disambiguating by `end_byte` would be a *behavior change* with its own
gate and is explicitly **out of scope** (but cheap to add later — see §5).

### §3.4 Read path

```rust
pub fn call_argument_texts_at(&self, start_byte: usize, callee_name: &str) -> Vec<String> {
    self.call_args_index()
        .by_call
        .get(&(start_byte, callee_name.to_string()))
        .map(|spans| spans.iter().map(|a| self.arg_text(a)).collect())
        .unwrap_or_default()
}

/// Derive an argument's text from its span, byte-identically to the legacy
/// `node_text(child).trim().trim_start_matches('&')`. Mirrors `node_text`'s
/// `utf8_text(...).unwrap_or("")` (panic-safe on a malformed span — yields "").
fn arg_text(&self, a: &CallArg) -> String {
    self.source
        .as_bytes()
        .get(a.start_byte..a.end_byte)          // `.get` not `[..]`: "" on out-of-range, no panic
        .and_then(|b| std::str::from_utf8(b).ok())
        .unwrap_or("")
        .trim()
        .trim_start_matches('&')
        .to_string()
}
```

**Text derivation byte-matches the legacy** (`src/ast.rs:4371-4373`):
`node_text(child).trim().trim_start_matches('&')`, where
`node_text == node.utf8_text(self.source.as_bytes()).unwrap_or("")` (ast.rs:153).
`arg_text` reproduces that exactly — same byte range; `.get(start..end)` +
`from_utf8(..).ok().unwrap_or("")` yields `""` on an out-of-range or non-UTF-8 span
(never a panic), mirroring `node_text`'s `utf8_text(...).unwrap_or("")`; same
`trim().trim_start_matches('&')`. The owned `Vec<String>` return and the consumer
signatures are unchanged.

`BTreeMap::get` needs `&(usize, String)`; `callee_name.to_string()` allocates one key
`String` per **lookup** (Step 5b does one lookup per *resolved callee* at a site —
the `for resolved in cg.resolve_call_site(site)` loop, not strictly per site). If a
flamegraph shows this matters, switch `by_call` to a nested
`BTreeMap<usize, Vec<(String, Vec<CallArg>)>>` keyed by `start_byte` then
linear-scanned by name (call nodes per start_byte ≤ 2 in practice) — deferred; the
simple keyed map is the default.

### §3.5 What stays unchanged

- `call_argument_texts` (line variant) and `collect_call_args` (line walk) —
  untouched (§2).
- `call_argument_texts_at` **signature** — unchanged; only its body.
- `collect_call_args_at` — removed from the production path; **retained as a
  `#[cfg(test)]` reference oracle** for the parity test (§4).
- The cache — `ParsedFile` is `#[derive(Clone)]`-only, never serialized (it holds
  the unserializable tree-sitter `Tree`); it is re-parsed on every load. The index
  lives only in memory during a build → **no `CACHE_VERSION` bump.**

## §4. Exact-parity strategy

This is a behavior-preserving refactor; the gate is byte-identical output.

1. **Reference oracle.** Keep the original `collect_call_args_at` verbatim under
   `#[cfg(test)]` as `collect_call_args_at_reference`. It is the ground truth the
   index is proven against. (Its semantics — `is_call_node` + `call_function_name`
   + `call_arguments` + `is_named` + `trim` + `trim_start_matches('&')` — are the
   ones `named_arg_spans` + §3.4 reproduce.)
2. **Corpus parity test** (lib unit test in `ast.rs`): one fixture for **every**
   `Language::all()` variant — Python, JavaScript, TypeScript, **Tsx**, Go, Java, C,
   C++, Rust, **Lua**, **Terraform/HCL**, **Bash** (reuse `tests/common` generators
   where they exist, plus inline fixtures). For **every** call node in each tree,
   assert `call_argument_texts_at(start_byte, name)` (index) ==
   `collect_call_args_at_reference(start_byte, name)` (walk). Include the
   language-specific arg shapes that differ — Bash command words / no-arg commands,
   HCL `function_arguments` — not just C-style `(a, b)`.
3. **Discriminating fixtures** — must include: multiple calls on one line
   (`f(a); g(b)`), nested calls (`f(g(x), h(y))`), the same-start-byte chain
   `a.b().c()` (distinct names) and `a.b().b()` (same name → outer wins), `&`-ref
   args (`f(&x, &&y)`), whitespace-padded args, zero-arg calls, and a method whose
   `start_byte` is queried with a non-matching name (→ empty).
4. **TDD order per task:** write the parity test against the reference first (it
   passes on the unchanged walk), then introduce the index and re-point
   `call_argument_texts_at`, then assert the test still passes (now exercising the
   index).

## §5. Reuse-readiness (documented, not built)

The value type is `Vec<CallArg>` (byte-spans), not `Vec<String>` (text), so the same
index can later serve consumers beyond Step 5b **without a structural rewrite**:

- **Interprocedural type / taint propagation.** The arg→param mapping the index
  feeds (Step 5b's DFG edges) is the substrate for cross-call flow. A span lets a
  consumer re-descend (`descendant_for_byte_range`) to the arg node and attach an
  inferred type, or use the span as an S2 byte-identity key — the basis for
  propagating a known arg type into the callee's parameter (and a return type back
  out). This is Plan B (`taint_reaches`) territory; S1.5 only makes the substrate
  reusable.
- **Call-resolution tracing.** Precise per-call arg spans + arity enrich a "why did
  this resolve / drop" trace and sharpen arity-based overload disambiguation
  (extends Phase-IP #100's `arg_count`). The decisions stay in `resolution.rs`; the
  trace would hang on the existing `Reason::Resolution` / additive `Evidence.reasoning`
  hooks. The index supplies evidence, not decisions.
- **The `a.b().b()` disambiguation** (§3.3) becomes a cheap, span-keyed follow-up if
  ever needed.

None of these are implemented in S1.5. This section exists so the representation
choice is intentional and the codex review judges it against a stated purpose, not
as speculative gold-plating. Behavior in S1.5 is identical to today.

## §6. Determinism & cache

- `CallArgsIndex.by_call` is a `BTreeMap` → sorted, deterministic iteration; the
  build walk is deterministic pre-order DFS with first-write-wins. No `HashMap`,
  no ordering nondeterminism.
- No serialization, no `CACHE_VERSION` bump (§3.5). Warm-path (cache hit) does not
  run Step 5b, so the index is a cold-build-only structure — warm timings are
  unaffected.

## §8. Risks

| risk | mitigation |
|---|---|
| Index diverges from the walk (parity bug) | §4 reference oracle + exhaustive corpus parity test; shared `named_arg_spans` extractor; TDD. |
| Same-`start_byte` call nodes mis-keyed | `(start_byte, name)` key + first-write-wins (§3.3), with the `a.b().c()` / `a.b().b()` fixtures pinning it. |
| Lazy `OnceLock` race under rayon | `OnceLock::get_or_init` is the documented thread-safe path; Step 5b is serial today regardless. |
| Per-lookup key `String` alloc | one alloc per call site (= legacy's per-lookup cost order); fallback nested-map design noted (§3.4) if profiled hot. |
| Memory growth (spans for all calls) | bounded by source size, freed with `ParsedFile`; spans (16 B/arg) are smaller than the pre-extracted Strings they replace. |
