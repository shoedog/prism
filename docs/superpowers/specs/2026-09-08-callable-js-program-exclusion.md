# D2 — present JavaScript target is not Program membership

This source-backed proof-requirements slice selects no admission policy. It does
not change producer/schema/options, resolve again, install dependencies, add roots
or make non-Program targets eligible. The exact fixed public population is20
occurrences/14 inventoried targets, not20 missing files.

The [audit](../../eval/receiver-closure/2026-09-08-callable-js-program-exclusion.md)
classifies the actual same-Program request/checker evidence and pinned compiler
exclusion mechanism. Nine source exact-ambient provider identities are distinct from
11 requests with no checker declaration; dynamic context remains unsupported.
Neither group changes S7's null-target exact-ambient contract.

## Proof requirements before any successor admission design

Keep four independent questions: selected filesystem target, captured asset/file
presence, configured Program source membership, and actual semantic provider identity.
An absent Program target does not negate physical presence; present JavaScript does
not establish a declaration/runtime export or executable class.

For any policy that consumes compiler exclusion, authenticate each actual request
occurrence and resolution object/index, final Program membership and exact compiler
options for that source (including redirect identity). Retain actual extension,
external-library flag, raw path/originalPath containment, effective JS-depth limit,
traversal depth and selected elide predicate. Distinguish callback resolution
diagnostics from the separate Program-inclusion diagnostic and import/JSDoc guards.
Do not derive these from an opaque options hash, a package name, a normalized target
suffix or the caller's root options when source redirection can apply. Obtain them
from the original compiler execution without a second resolver or filesystem probe.

For any ambient alternative, separately prove supported request context, same-Program
singleton provider/request declaration identity and augmentation/selection barriers.
The nine audited provider identities are not nine automatically admissible requests.
The11 no-declaration requests have no current type-source disposition. Diagnostic
silence and a successful package lookup cannot supply one.

## Required negative fixtures for a later implementation

- Depth zero versus one; explicit root and later shallower revisit; final Program
  membership distinct from a temporarily elided traversal.
- allowJs/checkJs/noImplicitAny combinations; empty resolver diagnostics with a
  nonempty Program-inclusion diagnostic; noResolve and non-JS targets.
- Project-reference redirects and different per-file options; raw originalPath
  with/without node_modules containment; lexical links versus canonical target IDs.
- Repeated requests for one target, same-genuine request/provider swaps, missing
  checker declaration, unsupported dynamic context, duplicate/augmented provider.
- Unrelated missing source path/type/lib or uncertain entries, outside/refused
  encounters, and asset absent/present changes never waive whole-Program barriers.

Capture behavioral RED against the then-current exact base before implementation.
These are requirements, not a claim that this docs-only slice has implemented or
passed that future matrix. Existing source/compiler evidence and packet parity are
the verification for D2; runtime/class authority and React.FC expansion remain out.
