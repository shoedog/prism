## Architecture correction (controller-set; the plan's cited mechanism is wrong — verified)

The plan suggested "verdict-affecting sanitizer evaluation reusing `FlowPath.cleansed_for`". Ground truth: `taint_reaches` NEVER builds `FlowPath`s — it uses `cpg.taint_trace_nodes(...)` → `Trace` (src/cpg/trace.rs:243, a NodeIndex parent tree; zero cleansing info). And `cleansed_categories_for_source` (src/algorithms/taint.rs:10703-10726) is per-source-FUNCTION-BODY, categories only, NOT path-proven — its own doc says so (:10700-10702). **Making a non-path-proven signal verdict-affecting would mint false negatives**: `user = input(); safe = html.escape(user); sink(user)` has a sanitizer in the body but the RAW variable reaches the sink — the verdict must stay `Reached` there.

**The corrected design — two distinct honesty tiers:**

1. **Path-proven sanitization → verdict — TRANSITION-BASED (codex spec-review BLOCKER fix; node-presence is NOT sufficient).** In witness mode, when `reachability == Reached`, walk the ALREADY-COMPUTED ordered witness chain (the same chain `witness_graph_for` walks — src/reasoning/shape.rs:247-302, called at taint_reaches.rs:177). The trace parent tree is a FIRST-PARENT BFS tree (src/cpg/trace.rs:73, :334) with same-line assignment-propagation edges from RHS uses to same-line defs (:475) — so "some chain node sits inside a sanitizer assignment" does NOT prove the transform is on the path. **The rule: `Sanitized` requires a contiguous chain window proving the sanitizing transition** — chain node[i] lies inside the sanitizer call's RHS/argument span, chain node[i+1] is the LHS def of that SAME assignment/declaration, and the chain continues from node[i+1] toward the sink. Mechanics: witness nodes are CPG `Variable` nodes with file/line/byte spans (via `to_var_location`); reconstruct the enclosing assignment from node[i]'s byte span via `ParsedFile`/tree-sitter, verify its RHS is a recognizer-matched sanitizer call AND node[i+1] is that assignment's defined variable. **JS/TS declaration forms MUST be handled** (`const safe = escape(user)` — `variable_declarator` is not treated as an assignment value by the generic helpers; add the declaration-node case).
   - Recognizer matching: reuse the machinery `function_body_cleansed_for` uses internally (src/algorithms/taint.rs:10604-10657: `active_recognizers()` + `call_path_matches` + optional `semantic_check`) across categories — **EXCEPT recognizers carrying a `paired_check`** (the Go path-traversal family, src/sanitizers/path.rs:13): those are EXCLUDED from verdict-affecting `Sanitized` (the CWE engine gives them sink-time guard validation at taint.rs:5986 which taint_reaches cannot replicate this slice — they stay advisory-only). Document BOTH divergences from the CWE engine (any-category vs per-category cuts taint.rs:5996; paired-check exclusion). If the window check passes: verdict becomes the NEW variant `Reachability::Sanitized` (wire string `"Sanitized"`).
   - This distinguishes the fixture's `sink(safe)` (chain passes through `safe = html.escape(user)` → `Sanitized`) from `sink(user)` (chain never touches the sanitizer assignment → stays `Reached`). BOTH cases must be tests.
2. **Function-body presence (not path-proven) → stays advisory.** The existing `Cleansed` warning + `sanitizers_present_in_source_fn` behavior is UNCHANGED for the non-path-proven case. No verdict change from body-presence alone.
