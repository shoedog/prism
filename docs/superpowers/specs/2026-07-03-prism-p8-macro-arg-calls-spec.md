## Problem (adjudicated `prism_fn` class)

Calls inside Rust macro arguments are invisible: `assert!(detect_weak_hash_identity(...))` (real case: src/algorithms/primitive_slice.rs:837) mints no CallSite, so `nav callers detect_weak_hash_identity` misses every assert-wrapped test call site. Root cause chain (all verified):
- `is_call_node` (src/languages/mod.rs:602-615) has no `macro_invocation` arm; `call_function_name` (:618-694) reads `function`/`name` fields a macro doesn't have.
- Even if it did: tree-sitter-rust parses macro args as flat token soup. `token_tree` children (node-types.json, tree-sitter-rust 0.24.2) are ONLY `identifier`/`_literal`/`self`/`super`/`crate`/`primitive_type`/`metavariable`/`token_repetition`/nested `token_tree` — **no `call_expression`, no `scoped_identifier`, no `field_expression`**. Punctuation (`.`, `::`, `,`, `!` …) is ANONYMOUS and merges into runs (`prec.right(repeat1(choice(...PUNCTUATION)))` grammar.js:238-246) — a single anonymous node's text can be `).` or `,&`. Identifiers and nested token_trees have REAL byte ranges in the original file.

**Scope guard: this is NOT the NS_MACRO macro-name-resolution increment** (docs/superpowers/specs/2026-06-17-prism-macro-resolution-deferred.md — stays deferred). We extract ordinary value calls appearing in macro ARGUMENTS. Derive/proc-macro-generated bodies stay out (adjudicated `oracle_artifact`).

## Architecture (settled — follow it)

**Transparency allowlist (the precision gate).** Only macros whose arguments are ordinary evaluated Rust expressions mint call sites. Allowlist (match on the macro name's LAST path segment, i.e. `std::assert` ≡ `assert`): `assert`, `assert_eq`, `assert_ne`, `debug_assert`, `debug_assert_eq`, `debug_assert_ne`, `vec`, `format`, `format_args`, `print`, `println`, `eprint`, `eprintln`, `write`, `writeln`, `panic`, `todo`, `unimplemented`, `unreachable`, `dbg`. Everything else — including `matches!` (its 2nd arg is a PATTERN where `Some(x)` is not a call), `stringify!`, `quote!`, `lazy_static!`, `tokio::select!` — is skipped and counted (`macro_arg_skipped_macros`). `write!`/`writeln!` first arg is a real expression (the writer) — fine. NOTE for the fixture: `stringify!(foo())` must NEVER mint an edge — pin it.

**Token-pattern extractor (offset-preserving — never re-parse text into a synthetic buffer; byte offsets are node identity in this codebase).** For a `macro_invocation` node whose `macro` field's last segment is allowlisted, walk its `token_tree` children **including anonymous nodes** (`node.child(i)`, not `named_children`) recursively:
- **Free call**: `identifier` node immediately followed by a nested `token_tree` whose text starts with `(` → candidate call, `callee_name` = identifier text. Qualified path `a::b::f(...)`: identifiers separated by anonymous `::` tokens — join into the qualified name (mirror how ordinary extraction represents `mod::f` / `T::m` in `callee_name`; grep an existing scoped call's CallSite to confirm the exact format).
- **Method call**: anonymous token whose text ENDS WITH `.` immediately before `identifier` + paren `token_tree` → method call, unknown receiver (qualifier: derive from the preceding token if it is a plain identifier, else None). These flow through the existing Rust unknown-receiver floor (multi-owner drop / single-owner demote / R6 candidate) — no new resolution logic.
- **Punctuation atoms (spec-review MAJOR — merged runs must be split).** Anonymous punctuation nodes carry RUNS (`!=`, `..`, `..=`, `?.`, `=>`, `::<` are single or merged tokens). Before pattern-matching, split each anonymous token's text into logical Rust punctuation atoms (`::`, `.`, `!`, `,`, `..`, `..=`, `=>`, `?`, `<`, `>`, `(`, `)` …). ONLY an exact standalone `!` atom (immediately after an identifier, immediately before a delimiter token_tree) indicates a nested macro — `!=` must NOT. ONLY a member-access `.` atom indicates a method call — range `..`/`..=` (e.g. `a..b()`) must NOT. Mandatory unit tests: `!=`, `..`, `..=`, `?.`, `=>`, `::<` streams.
- **Nested macro**: identifier + standalone-`!` atom + token_tree → do NOT mint a call for the macro name. Recurse into its token_tree ONLY if the nested macro is itself allowlisted; else skip subtree + count.
- **Keyword guard**: skip identifiers that are Rust keywords-usable-in-exprs (`if`, `match`, `while`, `for`, `loop`, `return`, `move`, `fn`, `unsafe`, `else`, `let`, `in`, `as`, `ref`, `mut`, `impl`, `dyn`, `break`, `continue`, `where`, `struct`, `enum`, `union`) and the contextual tokens `self`/`super`/`crate`/`Self` when they appear as the *callee* identifier.
- **Constructor guard (spec-review MAJOR — adjudicated: skip, don't mint).** A callee whose FINAL path segment starts with an uppercase letter (`Some(...)`, `Ok(...)`, `Foo(...)`, `path::Variant(...)`) is constructor-shaped and is SKIPPED + counted (`macro_arg_ctor_skips`). Rationale: tuple structs/enum variants are `callable: true` value bindings in the scope graph (walk/types.rs:66,:134), and with an incomplete graph the legacy name-fallback could mint a wrong Exact edge to an unrelated `fn Foo`. Skipping uppercase costs only non-idiomatic Rust. Negative fixture: `my_assert_target(Foo(1))`-style `Foo(...)` inside `assert!` + an unrelated in-repo `fn Foo` → no edge to it. NOTE: `T::new(...)`/`Type::method(...)` have lowercase FINAL segments and still mint (only the final segment is tested).
- **Turbofish (spec-review MINOR — adjudicated: skip this slice).** `f::<T>(x)` does not match the identifier+parens pattern (turbofish atoms intervene) — that is the DELIBERATE behavior; pin with a no-mint unit test and mention in the extractor doc comment.
- Struct-literal lookalike `Ident { .. }` (brace token_tree) is NOT a call — only paren token_trees mint.

**CallSite minting (the critical seam correction).** Minted sites get `kind: CallKind::Call` — NOT `CallKind::MacroInvocation`. Verified trap: `graph_callable_edge` (src/name_resolution/consumer.rs:67-70) routes `MacroInvocation` → `NS_MACRO` (macro-NAME namespace); our inner calls are value calls and must route `NS_VALUE`. **Plumbing (spec-review MAJOR — this is real work, not a flag):** the active extraction path returns TUPLES (src/ast.rs:5416 region) and `CallGraph` unconditionally derives kind via `call_kind_at` (src/call_graph.rs:935; also builders at :654 and :3092) — `call_kind_at` (:3485-3506) marks ANY Rust span under a `macro_invocation` ancestor as `MacroInvocation`, which would mis-route every minted site. Replace the extraction tuple with an explicit call-site metadata struct carrying optional `kind`/`origin` overrides, and update EVERY CallSite builder path (grep all constructors; at minimum :654, :935-context, :3092). `call_kind_at` behavior for pre-existing (grammar-parsed) sites must not change. Provenance: add `CallSiteOrigin::MacroArg` variant (src/call_graph.rs:57-61, today `Source | IndirectResolution`). Set `arg_count: None`, `arg_spread: false` (top-level comma counting in merged-punctuation token runs is unreliable; None is the safe arity-disambiguation fallback — document). `line`/`start_byte`/`end_byte` from the identifier..token_tree span (real original-file offsets).

**Scope-graph wildcard exemption (spec-review BLOCKER — without this the feature is dead on arrival).** Expression-position `macro_invocation` currently installs a `MacroWildcard` poison over the containing scope: src/name_resolution/rust_populator/walk/locals.rs:123 and walk/types.rs:403 (`walk_macro_invocation`); lookup treats it as poison (src/name_resolution/engine.rs:263) and Rust authoritative resolution drops on `None` (src/resolution.rs:1218). So `assert!(check(x))` would mint a site whose name `check` is POISONED by the very macro that contains it. Fix: transparent allowlisted macros introduce NO bindings into the enclosing scope (that is precisely what makes them transparent), so the populator must NOT install a `MacroWildcard` for a macro whose last path segment is in the allowlist. Define the allowlist ONCE as a shared constant (e.g. `TRANSPARENT_ARG_MACROS` in a location importable by both the populator and the extractor) — the two consumers must never drift. Non-allowlisted macros keep their wildcard poison exactly as today. Tests: populator unit test (allowlisted macro adds no wildcard; non-allowlisted still does); the `macro_arg_call` fixture must resolve **Exact under a complete Rust scope graph** (this is the BLOCKER's regression pin).
