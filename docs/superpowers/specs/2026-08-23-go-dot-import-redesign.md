## 2. Design

### 2.1 Extraction + plumbing
Per-file `go_dot_imports: BTreeSet<String>` (import paths declared with the `.` alias) AND the per-call-site **shadow fact** (r1-W2: at extraction time, using the `receiver_type_in_fn` occurrence-binding pattern with the live `ParsedFile`, record on each Go unqualified call site whether a lexical binding of the callee name is in scope — a serde-defaulted boolean carried through every CallGraph constructor: empty/skeleton/full/subset/remove_files/merge + serialization). Today's only dot-import awareness is the fail-closed bail in `go_type_alias/canon.rs:437` — untouched.

### 2.2 Resolution rung (fail-closed at every branch)
**Step 0 — dominance (r1-W1, r2-W1):** for a Go caller file with ≥1 dot-import, the poison/conflict examination runs BEFORE any unqualified `LocalDef`/`SamePackage` Exact is returned (resolution.rs:3045-3110): a local/same-package candidate stays Exact only if the file's dot-imports are all proven AND none of the proven packages exports the called name. **Internal conflict rule (r2-W1): ANY local/same-package survivor coexisting with ANY dot-import candidate ⇒ drop — NEITHER side ever mints Exact (in incomplete/invalid input neither target is proven); `go_dot_import_internal_conflict_drop` telemetry.** An external or unproven dot-import poisons even the local Exact (fail-closed).

Hook points for NEW resolution (rejection item 2): (a) the same-package **zero-survivor** branch (resolution.rs:3077, the `GoSamePkgAllFiltered` arm) consults dot-imports BEFORE dropping; (b) the unqualified free-call path where no same-directory candidate exists at all. At either hook, for a Go caller file:

1. **Shadow gate (item 3, r1-W2):** the call site's stored shadow fact is true ⇒ no dot-import resolution (`go_dot_import_shadow_drop`).
2. **Path proof:** every dot-import path of the file resolves through the PROVEN module graph to an in-repo package dir. **Any dot-import whose path is unproven or resolves outside the repo poisons the file (item 1/4): its exports are unenumerable, so global uniqueness is unprovable — NO dot-import resolution for any bare name in that file** (`go_dot_import_external_poison_drop` / `_unproven_path_drop`).
3. **Candidates:** for each proven dot-imported package dir — **precondition (r2-W2, hardened per r3-W1): the directory holds exactly ONE nonempty non-`_test` package clause. A mixed-clause directory POISONS the file exactly like an external/unproven import (its exports are untrustworthy, so global uniqueness is unprovable): NO dot-import resolution for any bare name in the file, and step 0's dominance poison applies — never a mere empty candidate set (`go_dot_import_mixed_clause_drop`)** — then its exported free functions with certain build-constraint visibility from the caller via **`exact_cross_package_visibility`** (go_owner_partition.rs:211-233 — r1-W3); `uncertain` ⇒ drop.
4. **Global uniqueness (item 4, r2-W1):** exactly ONE candidate across ALL of the file's dot-imported packages **AND zero local/same-package survivors** ⇒ Exact, `ResolutionKind::GoDotImport`; anything else ⇒ drop (`go_dot_import_ambiguous_drop` / `_internal_conflict_drop`), never two Exacts.
