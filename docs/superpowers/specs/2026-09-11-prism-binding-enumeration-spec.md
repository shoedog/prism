## 2. Goals / Non-goals

**Goals**
1. For every supported grammar, an explicit, closed table of the node kinds that (a) create a binding scope, (b) introduce a name (declaration, parameter, pattern, loop/with/except target, comprehension target, import alias, …), or (c) bound a nested callable / deferred body — with rulings per (language, kind, occurrence variant). No kind that can introduce a name is left implicit.
2. Replace the heuristic "language-generic uncertainty collector" of amendment 1c as the *authority* with the table; keep the heuristic as a lint and as the runtime safety net for grammar drift.
3. Settle B8 per construct: capture reads are `CfgIncomplete` where the construct's execution timing is unknown to the line CFG, and remain so in this task even for immediately-invoked bodies (§6.3, r1 W5); each construct is a ruling with a fixture, not "every".
4. Make ownership fail-closed **without breaking the parent's may-reaching contract**: an unclassified binder demotes only the uses its scope can affect, and a classified non-`DefSite` binder acts at its execution point (a mask within its scope, or a synthetic def in the reaching solve), so `Killed` is reported only when no admissible route survives (§6.4; r1 W3, r2 W3, r4 W1–W2).
5. One regression per table row — every row, `NotBinding` included — generated from the table and proven to parse the row's kind (§7.1, r1 W4).
6. Grammar-drift detection: a pinned digest of each grammar's `node-types.json`; a grammar upgrade that adds or removes candidate kinds fails a test until the table is reviewed.
7. Retire amendment 1c's "PROVISIONAL" status: its fail-closed default becomes a first-class row ruling (`Uncertain`) with a recorded reason and the §6.4 barrier.

**Non-goals**
- No change to the edge set, the cache *shape* beyond the one `FlowDoubt` variant in §6.4 (with its single version bump, §8.3), or the `--min-confidence` / `--resolution` surfaces. New dfg-stats counters are additive JSON (§8).
- No CFG timing or nested-body summary for nested callables (that is the future item §6.3 names); this task only decides *which* constructs need it.
- No per-occurrence `DefId` (B8, future item), no alias-relation changes (`AliasUnstable` stays), no interprocedural changes (Step 5b unchanged).
- No Tier-A `--quick` corpus re-anchor (DECISIONS item 12, separate lane); closeout uses the matrix and the byte controls.

### 4.2 Generated, then curated, then pinned

1. **Generate (Task E0).** A census example binary (sibling of `examples/dfg_census.rs`; exact path per the plan) walks each grammar's `node-types.json` and emits, per language, every named kind with: whether the *current* heuristic (`derive_introducing_fields`) flags it and which fields, whether `binding_scope_rule` classifies it, and the kind's occurrence count inside function bodies over the Tier-A corpus (`eval/tier_a/corpus.py` anchors). Output: one markdown table per language under the in-repo spec directory plus a JSON twin the tests read.
2. **Curate (Tasks E1–E4).** A controller pass assigns each candidate row its rulings (§6). Rows the heuristic flags but the curator rejects (e.g. `regex_pattern`, `class_heritage`, `type_parameter`) get `NotBinding` with a one-line reason and a case (§7.1); nothing is silently dropped.
3. **Pin.** The curated rows live in code as static data (not `match` arms), grouped per language, with the grammar digest per language: `sha256(node_types_json())` recorded next to the rows. `binding_scope_rule` becomes a lookup; the `match` at `scope.rs:410-474` is deleted. Module layout is the implementation plan's decision under the 600-line rule (§8.5).

### 4.3 Drift and totality tests (all RED-first)

- `binding_table_digest_matches_grammar` — for every `Language::all()`, `sha256(node_types_json()) == table.digest`. A grammar bump fails here with the kinds added/removed (census vs table) until re-curated.
- `binding_table_is_total_over_candidates` — every kind the heuristic flags *or* the census regex matches has at least one row (any ruling, `NotBinding` included). The heuristic stops being the classifier and becomes the lint that proves the table covers what it would have caught.
- `binding_table_rows_have_regressions` — **every** row (including `NotBinding`) names a case id; the case exists; the case's snippet, parsed with the row's language, **contains a node of exactly the row's kind** (asserted by the `case!` macro); and the case's assertions exercise the ruling (§7.1). A row can no longer point at a case for a neighbouring kind (r1 W4).
- `capture_table_covers_every_boundary_kind` — every `callable_boundary_node_types()` kind has a capture row with a `timing` (extends `capture.rs:121-131`).
- `uncertain_rows_carry_reasons` — every `Uncertain` ruling has a non-empty reason and a `revisit` pointer.

These are **coverage** gates (r4 S1): digest, totality, exclusivity over the supplied snippets and one case per row prove that every kind has a reviewed row and a parsing case, not that a predicate or an expected label is right outside those samples. Semantic correctness is carried by the per-row assertion partitions of §7.1 and by each task's proof obligations in §9; the spec claims no exhaustive semantic closure from kind coverage.

## 5. Table schema

Two keyed tables, joined by `(language, kind)` in tests, edited by different tasks (§9):

```rust
// binding table — one row per (language, kind, variant)
pub(crate) struct BindingRow {
    pub language: Language,
    pub kind: &'static str,                    // tree-sitter named kind
    pub variant: Option<Predicate>,            // locally decidable occurrence test, or None = all occurrences
    pub roles: RoleSet,                        // any of {Scope, Binding, NotBinding}; Scope|Binding may combine
    pub fields: &'static [&'static str],       // name-introducing fields for Binding rows (from node-types, not guessed)
    pub declaration: Option<DeclarationKind>,  // Parameter | GoShort | JavaScriptVar | PythonAssignment | Reuse (non-DefSite update, §6.4 2b) | Other | Pattern | CaptureCopy (§6.4 exemption)
    pub visibility: Visibility,                // WholeScope | AfterIntroduction | Header | Comprehension | Custom(id)
    pub ruling: Ruling,                        // Classified | Uncertain { reason, revisit }
    pub regression: &'static str,              // case id in the enumeration test corpus (§7.1)
}
// capture table — one row per (language, boundary kind, variant)
pub(crate) struct CaptureRow {
    pub language: Language,
    pub kind: &'static str,                    // a callable_boundary_node_types() kind
    pub variant: Option<Predicate>,            // same residual rule as BindingRow (r2 W2)
    pub timing: Timing,                        // Deferred | Immediate | Unknown  (§6.3)
    pub regression: &'static str,
}
```

- `Predicate` is a small closed enum of checks decidable from the node and its parent alone: `FieldTextIs { field, text }` (e.g. `for_in_statement.kind ∈ {let, const}` vs `var`), `OperatorIs { text }` (Go `range_clause` `:=` vs `=`), `ParentKindIs`, `HasField`, `IsImmediatelyInvoked` (r3 W1: walk upward through transparent `parenthesized_expression` ancestors — zero or more — and require the outermost such wrapper, or the boundary node itself when unwrapped, to be exactly the `function` field of a `call_expression`; any other parent of the outermost wrapper means *stored*, so `const f = (function(){});` is not invoked while `(function(){})()` and `(() => 0)()` are). The exclusivity snippets include both negatives: the stored-parenthesized form and the invoked forms. A kind with occurrence-dependent semantics gets one row per variant, each with its own regression (r1 W2). **Selection rule (r2 W1):** predicate rows are tried first; `variant: None` is *residual-only* — selected only when no predicate row of that (language, kind) matches. Predicate rows of one kind must be pairwise exclusive. The exclusivity test walks every occurrence of the kind in every regression snippet of the corpus and asserts **exactly one** row is selected (zero ⇒ missing residual; two ⇒ overlapping predicates). The same rule and test apply to the capture table.
- `RoleSet` lets Python `function_definition` be Scope + Binding (its name) at once; its capture-boundary role lives in the capture table (r1 W2).
- `Visibility::Header` expresses Go `if`/`for`/`switch` header scopes and JS/TS `for (let …)` headers as rows instead of special-case code (`scope.rs:609-620`).
- `Ruling::Uncertain` is the 1c fail-closed default made explicit, with the §6.4 barrier attached.
- Runtime safety net: a kind that appears in a parsed tree but has **no row** (a grammar upgrade that bypassed §4.3, or a hidden/supertype kind) is treated as `Uncertain { reason: "no table row" }`, counted (§8), and barred from Exact by §6.4.

## 6. Rulings per construct class

The label a row yields is the item 2 §4.3 label table plus the one new doubt in §6.4; the enumeration decides which RD outcome a construct feeds.

### 6.1 Scope creators (`Scope` role)
Ruling `Classified`. Python: function/lambda/class/comprehension bodies only (1b). JS/TS/TSX: `statement_block`, `class_body`, `class_static_block`, function bodies, `for`/`for_in` headers when `kind ∈ {let, const}` (variant), `catch_clause`, `switch_body`. Go: `block`, `if`/`for`/`expression_switch`/`type_switch`/`select` (header scopes), each `*_case` (its own implicit block). Rust: `block`, `unsafe_block`, `const_block`, `try_block`, `match_arm`, `let_chain`/`let_condition` (`if let` / `while let` header scope), closure bodies. Java: `block`, `switch_block_statement_group`, `catch_clause`, `enhanced_for_statement`, `for_statement`, `try_with_resources_statement`, lambda bodies. C/C++: `compound_statement`, `for_statement`, `for_range_loop`, `catch_clause`, lambda bodies. Lua: `block`, `for_numeric_clause`/`for_generic_clause`, `function_definition`. Bash/Terraform: `Uncertain` for everything name-introducing (census-only languages, Task 6b gate-9), reason "census-only language".

### 6.2 Bindings (`Binding` role)
- **Declarations that reuse** (kill): Go `short_var_declaration` in the same scope; Go `range_clause` variant `OperatorIs "="` (update) vs `":="` (declare, masks — r1 W2); JS `variable_declaration` (`var`, hoisted, function-scoped, parameter redeclaration reuses); Python `assignment`/`augmented_assignment`/`named_expression`; Lua plain `assignment_statement`; C/C++/Java `assignment_expression` to a declared name. `Classified`.
- **Declarations that mask** (new binding, dead at scope end): JS/TS `lexical_declaration`, Rust `let_declaration`, Go `var_declaration`/`const_declaration`, Java `local_variable_declaration`, C/C++ `declaration`/`init_declarator`, Lua `variable_declaration` (`local`). `Classified`.
- **Pattern bindings**: Rust `tuple_pattern`/`struct_pattern`/`tuple_struct_pattern`/`slice_pattern`/`or_pattern`/`ref_pattern`/`mut_pattern`/`captured_pattern` inside `let`, `if let`, `while let`, `match_arm`, `for_expression`, closure parameters; Python `pattern_list`/`tuple_pattern`/`list_pattern` targets, `case_pattern`/`class_pattern`/`as_pattern`/`keyword_pattern` in `match`; JS/TS `object_pattern`/`array_pattern`/`assignment_pattern`/`rest_pattern`/`shorthand_property_identifier_pattern`; Java `record_pattern`/`type_pattern` (incl. `instanceof R(var x)`); Go `type_case` bindings. Its specifier-line read (copy-now) lies outside the body range the capture walk records (`capture.rs:22`, `child_by_field_name("body")`) and takes ordinary RD on `main` **only when the specifier and the body read are on different lines** (r3 W2): capture references are keyed `(AccessPath, line)` (`capture.rs:9`, `:58-66`) and `is_capture` range-checks the *source* byte only (`:40-47`), so in the one-line form `auto f = [x]{ sink(x); };` the specifier `x` and the body `x` share one identity and the specifier-span edge is labelled `CfgIncomplete` today. The counter is the evidence B8 asked for: it shows per corpus how many edges the future item would touch, before any downgrade rule is relaxed.

### 6.4 The `Uncertain` barrier (r1 W3) and precedence
**Rule 1 — uncertain binders (scope-bounded; r4 W2).** A binder ruled `Uncertain` (or with no row) for the use's name marks that name UNCERTAIN only within the binder's **visibility span**: the scope span of the construct the row names as the binder's scope (its body from the binder's line to the scope's end — the same span `dominance_route_lines` already computes at `scope.rs:543-560`). For a use inside that span reached from the def, the label is `NameOnly(FlowDoubt::OwnershipUncertain { construct_line })`, never `Exact`, and the flat-path equation is not consulted for that pair. **After scope exit the doubt is discharged**: a use outside the span resolves by rule 2 and ordinary RD, so `let x = source(); if let Some(x) = opt { observe(); } sink(x);` keeps `1:x→3:x` `exact` even while Rust `tuple_struct_pattern` (sub-patterns are anonymous children; only a `type` field) stays `Uncertain` — the pattern cannot affect ownership past its `if let` block. **Unknown span ⇒ fail-closed**: a binder with no row, or whose scope construct the table cannot name, has the enclosing function as its span. Rationale for the demotion inside the span: the flat sets contain `DefSite`s only, so "no same-path def intervenes" proves nothing about ownership where a construct the table could not classify may have rebound the name. `NotBinding` rows are transparent.

**Rule 2 — classified binders that are not `DefSite`s, applied at their execution point (r2 W3, r4 W1).** A `Classified` binder of the use's name that has no `DefSite` (catch parameters, `except … as`, `with … as`, pattern bindings, function-local import aliases, Go `range` targets with `=`, Python `for` targets where not already lvalues) is never an unconditional kill applied before the flat fallback. It is applied by its row's declaration kind, on the binding-resolved path and on the flat-fallback path alike:
- **2a — masking binder** (new inner binding; `declaration: Other | Pattern`): a use inside the binder's scope span belongs to the inner binding, so the outer edge to it is `NameOnly(Killed { kill_line = binder line })` (the existing masking vocabulary; 1c's `2:x→3:x` is `killed@3`); a use outside the span is unaffected — the outer value survives every route through the scope because the inner binding was a different name. The mask is decided by binding identity (the `relation` machinery, `reaching.rs:409-415`), not by a route kill: a synthetic kill at the binder node would wrongly kill `if x := f(); c { … } sink(x)` (every route passes the header) — the same reason 2a is scope-based.
- **2b — reuse binder** (updates the outer binding; `declaration: GoShort-in-scope | JavaScriptVar | PythonAssignment | Reuse`): the binder is a genuine def of the outer binding at its execution point, so it is **synthesized as a def-like node** in the reaching solve at its AST node's CFG position (GEN a synthetic def, KILL the outer defs of that path, in both the binding-resolved and the flat sets); `classify_by_reaching_sets` over the existing successor graph then decides, and reports `Killed@binder` **only when no admissible unflagged route survives**. Hence `x := source(); for _, x = range items { observe() }; sink(x)`: inside the body every route passes the header assignment ⇒ `Killed@range`; after the loop the zero-iteration route header→exit survives ⇒ `exact` (Go permits zero iterations; main also keeps `exact` because no range `DefSite` exists — `ast.rs:4731`, `:9722` handle only `:=`). Conditional bypass (`if c { <reuse binder> } sink(x)`) is handled by the same mechanism. Binders that already are `DefSite`s need no synthesis; the census records which are.
The JS catch cases still mask because the catch parameter is a 2a mask whose span is the handler and every route into the handler passes it: `function f() { x = source(); try {} catch (x) { sink(x); } }` — undeclared outer (`FlatFallback`) and declared outer alike ⇒ `2:x→4:x` `nameonly/killed@3`; a `sink(x)` after the `try` stays `exact`. This refines amendment 1a/1b's "unconditional flat-path fallback", written when every table binder was a `DefSite`; it becomes part of amendment 1d (§6.5). `typescript/dfg_reaching_cfg_gap` has no binder on its route and stays `exact` (v6.5.2), pinned by §7.3. **Exemption (r3 W3): capture specifiers.** A C++ `lambda_capture_specifier` (and any future capture-list binder) is not a rule-2 binder: in `int x = source(); auto f = [x]{ sink(x); };` the outer value genuinely feeds the captured copy, so `Killed@capture-line` would be false and would contradict capture precedence (§6.3, `capture.rs:331-332`). Rule 2 skips rows carrying `declaration: Some(DeclarationKind::CaptureCopy)`; the specifier read and the inner capture edge are tested separately (§7.1).

**Which doubt and why.** A new variant rather than `CfgIncomplete`: item 2 §4.3 reserves `CfgIncomplete` for "RD could not run", and v6.5.2 rules that an unresolvable binding is not a `CfgIncomplete` doubt; conflating them would make the `CfgIncomplete` counter unreadable exactly where B8 wants it readable. Cost: `FlowDoubt` gains a variant ⇒ serialized `CpgEdge` payload changes ⇒ one `CACHE_VERSION` transition, **85 → 86 at afc78147** (`src/cpg_cache.rs:201`), re-resolved as current → current+1 at rebase time; the nav sidecar (`NAV_CALL_EDGE_CACHE_VERSION = 46`, `src/navigation/call_edge_cache.rs:90`) is untouched; cache-lifecycle tests updated (item 2 §4.6, §7.5) — a real payload plus a version bump, never `serde(skip)`. sol r2 endorsed the variant: `CfgIncomplete` would give a false edge-level reason and pollute its reserved counter, and an auxiliary construct-keyed counter cannot repair the label. Label-only: nominal-mode serializers do not print doubts, `--min-confidence` defaults to `nameonly` which admits it, so nominal bytes are unchanged; scoped/exact surfaces change and are matrix-gated (§8). 

**Scope.** Rule 1 keys on `construct_uncertain` (`reaching.rs:384-395`) restricted to the binder's visibility span, and on rows with no table entry (function span). Rule 2 keys on classified non-`DefSite` binders and runs on the resolved path and on the `lookup_uncertain` flat-fallback path (`reaching.rs:381-383`) alike, 2a as binding identity and 2b inside the reaching solve. A pair that is lookup-unresolved *and* crosses an uncertain construct inside its span takes rule 1. All of it is label-only: nominal bytes unchanged, scoped/exact surfaces gated per §8.

**Regressions (every downgrade paired with a mandatory preservation case; r4 S1).** Rule 1: `java-instanceof-pattern-uncertain` — `int x = source(); if (o instanceof R(var x)) { sink(x); }` on `main` `Exact` ⇒ `nameonly/ownership_uncertain@2` (inside-span demotion, RED on main) paired with `rust-if-let-uncertain-outside-scope` — `let x = source(); if let Some(x) = opt { observe(); } sink(x);` ⇒ `exact` (outside-span preservation, GREEN on main and must stay so), and `unknown-scope-fail-closed` (a boundary-less synthetic row ⇒ demotion to function end).
