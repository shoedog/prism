## 2. Decision record

Three shapes were escalated: **A** static table + full profile witnesses + consult-time ordering; **B** pure on-demand recompute (loses bare-lane RTA semantics); **C1** on-demand recompute **with consult-time RTA in the sol-r3-prescribed order** (`caller-profile filter → live selection → fallback`). ## 3. Design (normative)

### 3.1 Name→identity index (single universe)

`bare_name → BTreeSet<GoOwnerIdentity>` built from ALL recorded `go_interface_declarations` identities — regardless of `dispatchable`/`generic` (sol r2: one universe for caller-identity validation, the global fallback, AND collision counting; a dispatchable-restricted index reproduces r1 W1). Dispatchability is enforced inside the selected identity's walk, which fails closed on non-dispatchable declarations — the walk consumes the same declaration set, so there is still no index/build skew. **Identity selection order (c1-r3 W1): FIRST resolve the receiver type text against the caller via the existing `go_receiver_owner` machinery (imports/qualified text, resolution.rs:303-370) — a caller-resolved identity proceeds to §3.2 regardless of global same-name collisions (a valid `p.A` must not die to an unrelated `q.A`); ONLY unresolved bare text falls to the global index**: 0 identities → existing drop; ≥2 → existing no-impl drop path + `go_bare_iface_collision_drop` telemetry; unique → §3.2. No permissive fall-through.

**v8 — caller-resolved identity validation (etcd-24; owner 2026-08-23 "accept A, fold v8"):** a caller-resolved identity must itself exist among ALL recorded interface identities (the `go_interface_declarations` key set, REGARDLESS of `dispatchable`/`generic` — the extractor marks real declared interfaces `dispatchable: false` when generic or when any method signature is unsupported (type_providers/go.rs `record_interface_type`), so a dispatchable-restricted universe would misclassify them as phantoms and redirect dispatch to an unrelated same-name interface; sol r1 W1) before it proceeds to §3.2. The global-index fallback and its collision counting run over this SAME all-identities universe; dispatchability is enforced downstream by the selected identity's walk, which fails closed on non-dispatchable declarations. An identity absent from that universe is a mis-resolution witness, not a precision drop — measured mechanism (census, all 24 etcd floor sites): a constructor-local receiver whose constructor returns a package-qualified interface (`schema.NewAuthBackend(...) auth.AuthBackend`, auth.go:43) loses the qualifier in the receiver type text; the bare tail is attributed to the caller's own package, minting phantom `schema.AuthBackend` (schema declares no such interface), and the walk then yields `uncertain` → 24 sites drop 2→0. On validation failure the response depends on WHY the identity is absent — **v9 in-repo-qualifier gate (measured; owner-approved 2026-08-24)**. Absence has two causes and only one of them is a mis-resolution witness:
**The decision is made on RESOLVED TYPE PROVENANCE, never on receiver TEXT** (sol v9-r1 W1/W2/W3: text is not provenance — an external type can arrive BARE via `import . "time"` or `type Timer = time.Timer`, and an in-repo type can arrive QUALIFIED under an alias that rebinds to an external path in the using file). The predicate is **tri-state and fail-closed on anything unproven**:
  - **(a) PROVEN IN-REPO** — the receiver's type resolves to a package the analysis owns, established by an **exact effective import-path key** (never a directory-basename match — resolution.rs:349's `.or_else(package_basenames.get(seg))` fallback is expressly NOT admissible evidence for this gate: a repo containing `tools/time` would otherwise capture stdlib `"time"`; sol W3), or, for BARE receiver text, by the file being **free of dot-imports and of any in-scope alias/type-alias binding that name to an external path**. Absence from the interface universe is then a genuine mis-resolution witness ⇒ treat as UNRESOLVED and fall to the global index (0 → drop; ≥2 → collision drop; unique → §3.2 — etcd recovers `auth.AuthBackend`, store.go:197), counted `go_bare_identity_invalid_fallback`.
  - **(b) PROVEN EXTERNAL** — the type resolves through an exact import-path key to a path outside the analyzed module. Absence is CORRECT ⇒ **drop, no fallback**, counted `go_bare_identity_external_drop`.
  - **(c) UNPROVEN** — anything else: dot-imports present in the file, an alias whose target cannot be bound, an absent/incomplete module graph, a default import name the extractor may have mis-derived (`import "example.com/widget/v2"` is recorded under `v2`, not `widget` — ast.rs:2850; sol W3), or a cross-file type whose defining-file identity was not carried (`unique_visible_type` returns raw text without a `GoOwnerIdentity` — go_receiver_index_visibility.rs:200; sol W2). ⇒ **drop, no fallback**, counted `go_bare_identity_unproven_drop`, and enumerated in the census. Unproven never falls back: the recurring defect class across v7→v9 was always a cheap proxy standing in for provenance, and fail-closed-on-unproven is what structurally ends it — the residual risk becomes a MISSED recovery, never a false edge.
  **Implementation note (sol v9-r1):** the gate must read the resolved `receiver_type` (`time.Timer`), not `CallSite.qualifier` (`t`, a local variable); fixture (iii) exists to catch that mistake. Carrying cross-file types' defining-file `GoOwnerIdentity` (rather than re-resolving raw text in the using file) is the bounded fix for (c)'s cross-file case and moves those sites from unproven into (a).

  **Measured basis (v8 census, `16c1-census-v8/`):** across 4 corpora the v8 rule fired 1,200 fallbacks of which only 25 minted anything — 24 = the intended etcd recovery (all bare `AuthBackend`), 1 = a FALSE edge at hugo `internal/warpc/warpc.go:204`, where `putTimer(t *time.Timer)` calls `t.Stop()`: stdlib `time.Timer` is correctly absent, but v8 redirected it to the unrelated in-repo `debug.Timer` (tpl/debug/debug.go:143) and minted `{debug.nopTimerImpl, debug.timer}` — the signatures do not even agree (`Stop() bool` vs `Stop() string`). That site was correctly KILLED under v7, so v8 regressed the spec's own "all 8 over_approx die" gate to 7-of-8. The remaining 1,175 fallbacks are zero-identity drops that mint nothing either way; **their route labels are NOT all `external_drop`** (sol W4 — a correction to this document's own earlier claim: predeclared `error` is BARE, so it stays in (a); unbound default-name and ambiguous-module cases land in (c)). **Expected v10 mint delta vs the v8 census: hugo `Stop` returns to killed (8-of-8), etcd's 24 unchanged, no other mint changes** — controller pre-checked: the 24 etcd caller files carry no dot-imports and no local type aliases (so bare `AuthBackend` is provably in-repo under (a)), while hugo `warpc.go` imports `"time"` ordinarily (provably external under (b)). **Risk to disclose: if a corpus site's bare recovery turns out to be unprovable under (a), it moves to (c) and the recovery is LOST — the census, not this document, decides whether the 24 survive.** **The fallback fires ONLY on identity-validation failure — NEVER on walk failure of a validated identity**: a validated identity whose walk conflicts or is uncertain remains a fail-closed drop (the census's 7 prometheus `Put` walk-conflict kills and the hugo `Stop` walk-uncertainty kill depend on exactly this asymmetry). Root-causing the qualifier loss inside the receiver-owner machinery is a permitted implementation refinement; because that repair makes the caller-resolved identity VALID, every end-to-end etcd expectation accepts EITHER route — `validated_direct` or `identity_invalid_fallback` — provided the final Exact mints are identical (sol r1 W2). The fallback counter itself is pinned by an injected-phantom unit fixture, not by the end-to-end path. The validation gate remains the normative fail-safe contract either way.

### 3.2 The bare consult (ordering is the contract)

At resolution.rs:2773, for a unique identity, replace the table lookup with:

1. **Caller-scoped satisfaction walk** — one shared fn extracted from the proven lane (`select_interface_signatures_with_mode` + the satisfier walk in `go_visible_s4_implementers`, resolution.rs:1364-1470). Visibility primitives exactly as the proven lane splits them (c1-r1 S4): interface recursion uses owner/mode-aware `exact_declaration_visibility` (go_owner_partition_s4.rs:259); concrete method declarations use `exact_cross_package_visibility` (resolution.rs:1418). Ambiguity/`uncertain`/`conflict` ⇒ fail-closed drop. Satisfier method sets are the union of TWO caller-profile-safe sources (c1-r1 W1 — the proven walk alone misses embedded-struct-promoted methods that today's table records via `insert_sat_keys` over promoted method sets):
   - **direct**: `go_method_declarations`, caller-filtered as in the proven walk;
   - **promoted**: the R1(b) promoted-selector snapshot (`go_promoted_selector_snapshot`) **as repaired by R1(b)'s v5 amendment** (equal-depth field/method ⇒ shadowed, matching the static provider's `<=` rule — the c1-r2 W1 defect; C1 consumes only the repaired snapshot), consulted under EXACTLY the R1(b) rules (ProfileUnique + single declaration + exact variant coherence + not field-shadowed/ambiguous), **plus the R1(b) generic/signature guard (c1-r2 S3): join `promoted.target` to `go_method_declarations` by unique `FunctionId`, require `!generic && signature.is_some()`, and here additionally require the canonical signature to MATCH the interface method's signature (interface satisfaction needs it; the R1(b) same-selector mint does not)**. Anything else ⇒ that owner contributes no promoted entry, counted in census/telemetry — fail-closed, never a new comparator.
   The walk yields `(admission_key, FunctionId)` satisfier pairs (per-owner value/pointer matches compose `admission_key(type_name, is_pointer)`; promoted entries use the snapshot's `value_method_set`). The proven lane calls the SAME extracted fn for its direct source (behavior-preserving refactor, gated by proven-row byte comparison; whether the proven lane also gains the promoted source is a separate follow-up decision, NOT this slice — its rows must stay byte-identical).
2. **Live selection** — intersect satisfier admission keys with `CallGraph.go_interface_live_types` (already retained AND serialized, `#[serde(default)]`, populated in apply — call_graph.rs:677/3042). Non-empty ⇒ that subset.
3. **Fallback** — empty intersection ⇒ the full step-1 satisfier set, kept Exact, `go_bare_fallback_fired` telemetry — mirroring today's receiver-kind-aware-empty fallback (`NonLocalConstructionFallback` semantics), now profile-correct. **#18's gating applies to exactly this step later; out of scope here.**
4. **Arity filter** — the existing shared helper, in the same consult position it occupies today (after candidate selection); **an arity-emptied set routes through `func_value_field_or_external_drop` exactly as today's bare arm does (Ox r1 impl note; resolution.rs:2779-2799)**.
5. Mint Exact `InterfaceDispatch` from the survivors; telemetry `go_bare_walk_{sites,hits,edges}` + the collision/fallback counters, plumbed `ResolutionTelemetry` → queries accumulation → `call_stats` emission with drop-counter conservation.

## 9-PARK. ⛔ PARKED at the declared cap (2026-08-24) — OPEN-CLASS, escalated to owner. **v10 is NOT design-of-record; do not merge or implement this branch.**

sol r2 (final round of the declared 2-round cap) returned FIX and, when asked to classify, marked its lead finding **OPEN-CLASS**. The controller confirms and parks rather than extending.

**The recurring class:** every revision has substituted a cheaper proxy for *what interface the receiver actually binds to* — v7 the `dispatchable` filter → v8 universe membership → v9 the receiver-text qualifier → v10 absence-of-two-hazards. Each round a new instance appears. sol's v10 instances: a **generic type parameter** (`func f[T interface{ M(); N() }](x T) { x.M() }`) is neither dot-import nor alias, so rule (a) falls back to an unrelated recorded `a.T` and can mint an implementer lacking `N`; **local type declarations and type shadowing** are likewise uncovered; and **predeclared `error`**, which §W4's own correction routes to "proven in-repo", has universe-block provenance. Controller-verified in source: type parameters are **not modeled at all** in receiver typing (no `type_parameter` handling in `resolution.rs`/`go_receiver_index.rs`), and `proof_shadowed` covers only *value* shadowing (resolution.rs:599-601), not type shadowing.

**The deeper consequence — this reaches the already-approved v8 gate, not only the fallback:** if a second package also declares the shadowed name, all-identities validation *succeeds* and the tri-state is bypassed entirely. **Membership proves a declaration exists; it does not prove the receiver binds to it.** No further exclusion closes this — closure requires positive, scope-aware binding at the receiver's type-origin (predeclared identifiers, type parameters, local declarations/shadowing, aliases, carried identities) *before* validation.

**Two findings ARE closed-enumerable and remain owed to whichever option is chosen** (sol r2 W2/W3): the keyed census is still not a classifier oracle — it needs an independently derived *expected* route per site key with actual-vs-expected equality, not merely reported dispositions and counts (an implementation could label every zero-mint external site `invalid_fallback`, preserve all mints, and pass); and `validated_direct` must be added to the exhaustive route partition or explicitly excluded and accounted separately, since §5 currently both requires exactly-one-of-three and permits it.

**Measured stakes for the owner's choice.** Across 4 corpora the identity-invalid fallback fires **1,200 times and buys exactly 24 mints** (etcd `AuthBackend`) — plus the 1 false edge v9/v10 were written to remove. **Every other C1 win comes from the caller-scoped satisfaction walk, live-set intersection, and collision-drop — not from the fallback:** all 7 prometheus `Put` over-approx kills (walk conflict), caddy `metrics.go:56` (collision drop), caddy's +6 qualified identities, and the preserved `CaddyModule`/`CertMagicStorage` floors.

**Options escalated (owner decision):**
- **(B) Ship C1 without the identity-invalid fallback** — keep the walk, live-set, and collision semantics; on validation failure simply drop. Keeps every precision win, forfeits only the etcd-24 recovery, carries **zero** open-class exposure, and is a one-rule deletion from v8. *Controller recommendation.*
- **(A) Build positive receiver type-binding first** — scope-aware type-origin resolution (predeclared, type params, local decls/shadowing, aliases, carried identities). Ends the class and unlocks etcd-24 and more, but it is a subsystem, not a spec amendment; it should be its own design with its own plan.
- **(C) Narrow C1 to positively-resolvable receivers only** — apply the bare consult solely where the type-origin is provable today (exact import-path key, unshadowed), drop the rest. Between (A) and (B) in both cost and yield.
