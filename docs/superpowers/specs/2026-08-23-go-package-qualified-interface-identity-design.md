## 1. Problem (unchanged; measured on mainD)

The bare R3 interface ladder consults `interface_impls`, a build-time table keyed by bare interface name, whose satisfaction is computed over bare-collapsed last-writer maps. Measured residue: all 8 oracle over_approx sites (7× prometheus `Put`→`pool`, 1× hugo `Stop`) + caddy metrics.go:56 `ServeHTTP` (unscored, mechanism-confirmed) arrive through this consult; the same consult carries the sound caddy `CaddyModule` 11×fanout-121 registry recall + `CertMagicStorage` + etcd's 24 sound sites (#17b audit) — the recall floor.

## 2. Decision record

Three shapes were escalated: **A** static table + full profile witnesses + consult-time ordering; **B** pure on-demand recompute (loses bare-lane RTA semantics); **C1** on-demand recompute **with consult-time RTA in the sol-r3-prescribed order** (`caller-profile filter → live selection → fallback`). Owner picked **C1**. Rationale: sol's r2/r3 counterexample class (profile witnesses, embedded flattening, live/fallback ordering) is *structural* to build-time tables; C1 reuses the proven lane's caller-scoped machinery — one implementation, no skew class — while preserving today's RTA/fallback semantics as an explicit, gateable consult step (where #18's fallback gating later lands). **Preservation claim scoped precisely (Ox r1 S1/S2): the walk's fail-closed strictness and the visible-set fallback condition CAN diverge from today's unfiltered table on specific sites — every such delta is forced into the open by §4's census categories, never silent.**

## 3. Design (normative)

### 3.1 Name→identity index (single universe)

`bare_name → BTreeSet<GoOwnerIdentity>` built from ALL recorded `go_interface_declarations` identities — regardless of `dispatchable`/`generic` (sol r2: one universe for caller-identity validation, the global fallback, AND collision counting; a dispatchable-restricted index reproduces r1 W1). Dispatchability is enforced inside the selected identity's walk, which fails closed on non-dispatchable declarations — the walk consumes the same declaration set, so there is still no index/build skew. **Identity selection order (c1-r3 W1): FIRST resolve the receiver type text against the caller via the existing `go_receiver_owner` machinery (imports/qualified text, resolution.rs:303-370) — a caller-resolved identity proceeds to §3.2 regardless of global same-name collisions (a valid `p.A` must not die to an unrelated `q.A`); ONLY unresolved bare text falls to the global index**: 0 identities → existing drop; ≥2 → existing no-impl drop path + `go_bare_iface_collision_drop` telemetry; unique → §3.2. No permissive fall-through.

**v11 — identity validation WITHOUT a fallback (owner decision 2026-08-24: "ship B, then A").** A caller-resolved identity is VALIDATED against the all-identities universe (`go_interface_declarations` keys, regardless of `dispatchable`/`generic` — the extractor marks real interfaces non-dispatchable when generic or when a method signature is unsupported, type_providers/go.rs `record_interface_type`). **On validation failure the site DROPS**, counted `go_bare_identity_invalid_drop`. There is NO re-entry into the global index on validation failure. (Unresolved *bare* receiver text still reaches the global index exactly as in the pre-v8 design — 0 → drop, ≥2 → collision drop, unique → §3.2. That path is unchanged and is not the removed fallback.)

*History, condensed (full record in PR #201, parked):* v9/v10 tried to make an identity-invalid fallback safe — first via a receiver-text qualifier test, then a provenance tri-state. Review classified the result **open-class**: every revision substituted a cheaper proxy for *what the receiver actually binds to* (v7 the `dispatchable` filter → v8 universe membership → v9 text qualifier → v10 absence-of-hazards), and each round produced a new instance. Membership proves a declaration exists; it does not prove the receiver binds to it. B removes the fallback instead of approximating it.

Note the gate is **DIAGNOSTIC, not load-bearing**: a phantom identity that walked instead would yield `uncertain` and drop anyway — v7's measured behaviour at all 24 etcd sites. Validating first buys a clean counter and a census key, not a different mint. It must never be described as a correctness mechanism.

**What B forfeits, measured:** the identity-invalid fallback fired **1,200 times across four corpora and minted at exactly 25 sites** — 24 = the etcd `AuthBackend` recovery, 1 = the hugo `warpc.go:204` false edge (stdlib `*time.Timer` redirected to unrelated in-repo `debug.Timer`; signatures `Stop() bool` vs `Stop() string`). B gives up the etcd-24 recall win and removes that false edge for free. **Every other C1 win is downstream of the walk and unaffected:** all 7 prometheus `Put` over-approx kills (walk conflict), caddy `metrics.go:56` (collision drop), caddy's +6 qualified identities, and the preserved `CaddyModule` / `CertMagicStorage` floors.

**What B does NOT close — the residual, now enumerable.** The open class is that universe membership ≠ binding: generic type parameters, local type declarations, type shadowing, and predeclared identifiers can all make a validated identity the wrong one. Controller-verified in source: type parameters are **unmodeled** in receiver typing, and `proof_shadowed` (resolution.rs:599-601) covers only **value** shadowing. B does not fix this — it **shrinks the binding-dependent surface from 1,363 sites to 163**: `validated_direct` (hugo 11 + prometheus 7 = 18) and `unique_index` (caddy 18 + etcd 101 + hugo 11 + prometheus 15 = 145). Two properties make that an acceptable shipping state: (1) `unique_index` is the ORIGINAL pre-v8 design, not something these amendments introduced; (2) 163 is small enough to audit exhaustively (§4 binding audit), so the residual ships as a NAMED, inspected list rather than an unbounded risk. C1-B is also strictly narrower than today's bare-collapsed `interface_impls` lookup at every one of those sites — a narrowing, never a widening.

**Follow-on (A), sequenced after B ships:** positive, scope-aware receiver type-origin binding — predeclared identifiers, type parameters, local declarations and shadowing, aliases, carried cross-file identities — resolved BEFORE validation. That is a subsystem and gets its own design and plan, not an amendment here. B is deliberately shaped so A is additive: A replaces only the identity-determination step, while the walk, live-set intersection, collision drop, arity filter, and telemetry B ships are downstream and unchanged. **A's acceptance target is crisp precisely because B ships first: recover the 24 etcd sites B forfeits, with zero false edges, and clear the §4 binding-audit residual.**

### 3.2 The bare consult (ordering is the contract)

At resolution.rs:2773, for a unique identity, replace the table lookup with:

1. **Caller-scoped satisfaction walk** — one shared fn extracted from the proven lane (`select_interface_signatures_with_mode` + the satisfier walk in `go_visible_s4_implementers`, resolution.rs:1364-1470). Visibility primitives exactly as the proven lane splits them (c1-r1 S4): interface recursion uses owner/mode-aware `exact_declaration_visibility` (go_owner_partition_s4.rs:259); concrete method declarations use `exact_cross_package_visibility` (resolution.rs:1418). Ambiguity/`uncertain`/`conflict` ⇒ fail-closed drop. Satisfier method sets are the union of TWO caller-profile-safe sources (c1-r1 W1 — the proven walk alone misses embedded-struct-promoted methods that today's table records via `insert_sat_keys` over promoted method sets):
   - **direct**: `go_method_declarations`, caller-filtered as in the proven walk;
   - **promoted**: the R1(b) promoted-selector snapshot (`go_promoted_selector_snapshot`) **as repaired by R1(b)'s v5 amendment** (equal-depth field/method ⇒ shadowed, matching the static provider's `<=` rule — the c1-r2 W1 defect; C1 consumes only the repaired snapshot), consulted under EXACTLY the R1(b) rules (ProfileUnique + single declaration + exact variant coherence + not field-shadowed/ambiguous), **plus the R1(b) generic/signature guard (c1-r2 S3): join `promoted.target` to `go_method_declarations` by unique `FunctionId`, require `!generic && signature.is_some()`, and here additionally require the canonical signature to MATCH the interface method's signature (interface satisfaction needs it; the R1(b) same-selector mint does not)**. Anything else ⇒ that owner contributes no promoted entry, counted in census/telemetry — fail-closed, never a new comparator.
   The walk yields `(admission_key, FunctionId)` satisfier pairs (per-owner value/pointer matches compose `admission_key(type_name, is_pointer)`; promoted entries use the snapshot's `value_method_set`). The proven lane calls the SAME extracted fn for its direct source (behavior-preserving refactor, gated by proven-row byte comparison; whether the proven lane also gains the promoted source is a separate follow-up decision, NOT this slice — its rows must stay byte-identical).
2. **Live selection** — intersect satisfier admission keys with `CallGraph.go_interface_live_types` (already retained AND serialized, `#[serde(default)]`, populated in apply — call_graph.rs:677/3042). Non-empty ⇒ that subset.
3. **Fallback** — empty intersection ⇒ the full step-1 satisfier set, kept Exact, `go_bare_fallback_fired` telemetry — mirroring today's receiver-kind-aware-empty fallback (`NonLocalConstructionFallback` semantics), now profile-correct. **#18's gating applies to exactly this step later; out of scope here.**
4. **Arity filter** — the existing shared helper, in the same consult position it occupies today (after candidate selection); **an arity-emptied set routes through `func_value_field_or_external_drop` exactly as today's bare arm does (Ox r1 impl note; resolution.rs:2779-2799)**.
5. Mint Exact `InterfaceDispatch` from the survivors; telemetry `go_bare_walk_{sites,hits,edges}` + the collision/fallback counters, plumbed `ResolutionTelemetry` → queries accumulation → `call_stats` emission with drop-counter conservation.
