## Reason audit

- `report_analysis.py` — Declaration limits use `declaration_changes` records with a check, owner or counterpart side, file, revision and source reason. File-local proof and the broader operation-absence proof are independent. Schema limits consume admitted schema diagnostics. Client site observations carry enclosing-function, diff or inventory failures. Standing timing carries comparison-specific failures. Count reasons come from the first applicable missing population, match or proof. Earlier bindings, overlap coverage and field-use limitations describe the fixed scope of the adapter.
- `report_markdown.py` — Warning locations come from frozen diagnostics. Empty change sections and counts share their population failure. Match cells read the stored match proof and registration reason. Call rows read the absence or correspondence record. Mapping, enclosing function and caller notices follow the corresponding missing records. Standing rows read timing failures and the recorded registration limitation. The request appendix uses the named pair and preserves observed targets and counts.
- `report_layout.py` — The shared limit table groups matching diagnostics and retains their affected sites. Review first uses the lead row or the count failure. Versions and provenance use the selected commit, searched tip, cutoff, and source receipts. Coverage reads the schema result and unavailable counterpart record. Duration is derived from the two committer timestamps.
- `report_sources.py` — Service diagnostics come from root checks, blob or parse outcomes, annotation or entry validation, and the changed registration region inventory. Client diagnostics come from the supplied configuration receipt, file reads and parsing, primary client and import checks, unsupported aliases and dependency parsing. Source diagnostics retain the affected path and line. Tests excluded from client scope are recorded as exclusions.
- `report_operations.py` — Operation presence, other-prefix checks and closest-match counts use their own proof or inventory check. Validation, handler, field location, format and enum notices reflect the evidence each extractor supplies. File-local rows link the changed declaration sites, and mixed call rows render the named pair.
